При определении переменных окружения в файле `.env` учитывайте следующее:

- Файл `.env` позволяет удобно задавать переменные окружения, которые работают как в CLI, так и в расширении для VS Code.
- Рекомендуем размещать файл `.env` в корневом каталоге проекта и запускать команды dbt из этого каталога, поскольку файл загружается _только_ из текущего рабочего каталога. Загрузка файла не поддерживает флаг `--project-dir` или переменную окружения <VersionBlock lastVersion="1.10">`DBT_PROJECT_DIR`</VersionBlock><VersionBlock firstVersion="1.11">`DBT_ENGINE_PROJECT_DIR`</VersionBlock>, и dbt не будет искать файл в корневом каталоге проекта, если вы запускаете команды из другого каталога.
- Добавьте `.env` в файл `.gitignore`, чтобы конфиденциальные учетные данные не попали в репозиторий при коммите.
- Переменные окружения, заданные непосредственно в командной оболочке (например, `export DBT_ENV_VAR=value`), имеют приоритет над значениями, определенными в файле `.env`.
