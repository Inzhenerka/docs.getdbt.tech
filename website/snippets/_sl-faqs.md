<DetailsToggle alt_header="Является ли dbt Semantic Layer открытым исходным кодом?">

<Constant name="semantic_layer" /> — проприетарный продукт; однако некоторые компоненты <Constant name="semantic_layer" />, такие как <Constant name="dbt" /> и MetricFlow, имеют открытый исходный код.

Пользователи <Constant name="dbt_platform" /> с тарифным планом Developer или пользователи <Constant name="dbt" /> могут определять метрики в своём проекте, в том числе в локальном проекте <Constant name="dbt" />, используя <Constant name="studio_ide" />, <Constant name="platform_cli" /> или dbt CLI. Однако для использования универсального <Constant name="semantic_layer" /> и доступа к этим метрикам через API или инструменты, использующие эти данные, необходим тарифный план <Constant name="dbt_platform" /> [Enterprise или Enterprise+](https://www.getdbt.com/pricing/).

Дополнительную информацию см. в разделе <a href="https://docs.getdbt.com/docs/platform/billing">Оплата</a>.

</DetailsToggle>

<DetailsToggle alt_header="Как пользователи с открытым исходным кодом могут использовать dbt Semantic Layer?">

Для работы <Constant name="semantic_layer" /> необходимо использовать предоставляемый <Constant name="dbt" /> сервис для координации запросов. Пользователи версии с открытым исходным кодом, которые не используют <Constant name="dbt" />, пока могут обойти отсутствие сервисного слоя. Для этого нужно выполнить команду `mf query --explain` в командной строке. Эта команда генерирует SQL-код, который затем можно использовать в существующих системах для выполнения запросов и управления ими.
  
По мере доработки API-слоёв MetricFlow некоторым пользователям может оказаться проще настроить собственные кастомные сервисные слои для управления запросами. В настоящий момент это не рекомендуется, так как границы API вокруг MetricFlow ещё недостаточно чётко определены для широкого использования сообществом.

</DetailsToggle>

<DetailsToggle alt_header="Почему результат моего запроса в CLI платформы dbt ограничен 100 строками?">

По умолчанию параметр `limit` для запросов, выполняемых из <Constant name="platform_cli" />, равен 100 строкам. Мы установили это значение по умолчанию, чтобы предотвратить возврат излишне больших наборов данных, поскольку <Constant name="platform_cli" /> обычно используется для запросов к семантическому слою dbt в процессе разработки, а не для формирования отчётности в рабочей среде или доступа к большим наборам данных. В большинстве рабочих процессов достаточно получить лишь часть данных.
  
При необходимости вы можете изменить это ограничение, указав параметр `--limit` в запросе. Например, чтобы вернуть 1000 строк, можно выполнить команду `dbt sl list metrics --limit 1000`.

</DetailsToggle>

<DetailsToggle alt_header="Могу ли я ссылаться на запросы MetricFlow внутри моделей dbt?">

dbt полагается на макросы Jinja для компиляции SQL, в то время как MetricFlow основан на Python и выполняет прямую рендеринг SQL, ориентированную на конкретный диалект. MetricFlow не поддерживает сквозную рендеринг макросов Jinja, поэтому мы не можем легко ссылаться на запросы MetricFlow внутри моделей dbt.

Помимо технических сложностей, которые можно было бы преодолеть, мы видим метрики как конечный узел вашего DAG и место для потребления метрик пользователями. Если вам нужно выполнить дополнительную трансформацию поверх метрики, это обычно является признаком того, что требуется больше моделирования.

</DetailsToggle>

<DetailsToggle alt_header="Могу ли я создавать таблицы в моей платформе данных с помощью MetricFlow?">

Вы можете воспользоваться готовящейся к выпуску функцией Exports, которая позволит создавать таблицу на вашей платформе данных на основе [заранее определённого](/docs/build/saved-queries) запроса MetricFlow. Эта функция будет доступна только клиентам <Constant name="dbt" />. Это связано с тем, что MetricFlow предназначен главным образом для формирования запросов, тогда как отправка соответствующего запроса и выполнение любых операций DDL относятся к задачам сервисного слоя, работающего поверх MetricFlow.

</DetailsToggle>

<DetailsToggle alt_header="Как вы храните мои данные?">

Данные пользователей проходят через Semantic Layer на пути обратно из хранилища. dbt Labs обеспечивает безопасность, аутентифицируясь через хранилище данных клиента. В настоящее время мы не кэшируем данные на длительный срок, но они могут временно оставаться в системе до 10 минут, обычно меньше. В будущем мы введем функцию кэширования, которая позволит нам кэшировать данные на нашей инфраструктуре до 24 часов.

</DetailsToggle>
