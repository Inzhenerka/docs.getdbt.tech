Вы должны входить в группу Owner и иметь соответствующую [лицензию](/docs/platform/manage-access/seats-and-users) и [права доступа](/docs/platform/manage-access/enterprise-permissions), чтобы администрировать Semantic Layer на уровне среды и проекта.
- Тарифные планы Enterprise+ и Enterprise:
  - Лицензия Developer с правами Account Admin или
  - Роль Owner с лицензией Developer и назначенными правами Project Creator, Database Admin или Admin.
- Тарифный план Starter: роль Owner с лицензией Developer.
- Бесплатный пробный период: вы используете бесплатную пробную версию тарифного плана Starter в роли Owner, а значит, у вас есть доступ к dbt Semantic Layer.
### 1. Выберите окружение {#1-select-environment}

Выберите окружение, в котором вы хотите включить Семантический слой:

1. Откройте **Account settings** в меню навигации.
2. В разделе **Settings** нажмите **Projects** и выберите проект.
3. На странице **Project details** найдите раздел **Semantic Layer** и нажмите **Configure Semantic Layer**.

<Lightbox src="/img/docs/dbt-platform/semantic-layer/new-sl-configure.png" width="70%" title="Раздел Semantic Layer на странице «Сведения о проекте»"/>

4. На странице **Set Up Semantic Layer Configuration** выберите окружение развёртывания для Semantic Layer и нажмите **Save**.

<Lightbox src="/img/docs/dbt-platform/semantic-layer/sl-select-env.png" width="75%" title="Выберите среду развертывания, в которой будет работать ваш семантический слой."/>

### 2. Настройка учетных данных и создание токенов {#2-configure-credentials-and-create-tokens}

Для настройки <Constant name="semantic_layer" /> с токенами API есть два варианта:

- [Добавить учетные данные и создать сервисные токены](#add-a-credential-and-create-service-tokens)
- [Настроить учетные данные для разработки и создать персональные токены](#configure-development-credentials-and-create-a-personal-token)

#### Добавление учётных данных и создание сервисных токенов {#add-a-credential-and-create-service-tokens}

Первый вариант — использовать [сервисные токены](/docs/dbt-apis/service-tokens) для аутентификации. Эти токены связаны с учетными данными платформы данных, которые вы предварительно настраиваете. Настроенные учетные данные используются для выполнения запросов, которые Semantic Layer отправляет к вашей платформе данных.

Эти учетные данные контролируют физический доступ к данным, к которым обращается Семантический слой, и все политики доступа, установленные на платформе данных для этих учетных данных, будут соблюдаться.

| Возможность | Тариф Starter | Тарифы Enterprise+ и Enterprise |
| --- | --- | --- |
| Service tokens | Можно создать несколько service token, связанных с одними учётными данными (credential). | Можно использовать несколько credential и привязывать к каждому из них несколько service token. Обратите внимание, что один service token нельзя привязать более чем к одному credential. |
| Credentials per project | Один credential на проект. | Можно [добавить несколько](#4-add-more-credentials) credential на проект. |
| Привязка нескольких сервисных токенов к одним учётным данным | ✅ | ✅ |

*Если вы используете тариф Starter и вам нужно добавить больше credential, рассмотрите возможность перехода на [Enterprise+ или Enterprise plan](https://www.getdbt.com/contact). Все пользователи Enterprise могут обратиться к разделу [Add more credentials](#4-add-more-credentials) для получения подробных инструкций по добавлению нескольких credential.*

##### 1. Выберите среду развертывания {#1-select-deployment-environment}
   - После выбора deployment environment вы увидите страницу **Credentials & service tokens**.  
   - Нажмите кнопку **Add Semantic Layer credential**.  

##### 2. Настройте учетные данные {#2-configure-credential}
   - В разделе **1. Add credentials** введите учетные данные, специфичные для вашей data platform, которые Semantic Layer будет использовать.
   - Используйте учетные данные с минимально необходимыми правами. Semantic Layer требует доступ на чтение к схемам, содержащим dbt models, используемые в ваших semantic models для downstream‑приложений.
   - <SLEnvVars/>

<Lightbox src="/img/docs/dbt-platform/semantic-layer/sl-add-credential.png" width="55%" title="Добавьте учетные данные и свяжите их с сервисным токеном. " />

##### 3. Создайте или привяжите сервисные токены
   - Если у вас есть разрешение на создание сервисных токенов, после добавления учетных данных вы увидите [опцию **Map new service token**](/docs/use-dbt-semantic-layer/setup-sl#manage-from-service-token-page). Укажите имя токена, задайте разрешения 'Semantic Layer Only' и 'Metadata Only' и нажмите **Save**. 
   - После создания токена вы больше не сможете его просмотреть, поэтому обязательно сохраните его в надежном месте.
   - Если у вас нет прав на создание сервисных токенов, вы увидите сообщение с предложением обратиться к администратору, чтобы он создал токен для вас. Администраторы могут создавать и привязывать токены по мере необходимости.
   <Lightbox src="/img/docs/dbt-platform/semantic-layer/sl-credential-no-service-token.png" width="70%" title="Если у вас нет прав на создание сервисных токенов, вы можете создать учетные данные и обратиться к администратору, чтобы он создал для вас токен." />

:::info
- Тариф Starter позволяет создавать несколько service token, привязанных к одному базовому credential, однако в каждом проекте может быть только один credential.
- Все тарифы Enterprise позволяют [добавлять несколько credential](#4-add-more-credentials) и связывать их с service token для более гибкого управления доступом.

#### Настройте учетные данные для разработки и создайте персональный токен {#configure-development-credentials-and-create-a-personal-token}

Использование [персональных токенов доступа (PAT)](/docs/dbt-apis/user-tokens) также поддерживается в качестве метода аутентификации в dbt <Constant name="semantic_layer" />. Это обеспечивает аутентификацию на уровне пользователя, снижая необходимость совместного использования токенов несколькими пользователями. При аутентификации с помощью PAT запросы выполняются с использованием ваших личных учетных данных.

Чтобы использовать PAT в <Constant name="semantic_layer" />:

1. Настройте свои учетные данные.
   1. Нажмите на имя своей учетной записи в нижней части меню слева и перейдите в **Account settings** > **Credentials**.
   2. Выберите свой проект. 
   3. Нажмите **Edit**.
   4. Перейдите в **User credentials** и введите свои данные. 
   5. Нажмите **Save**.
2. [Создайте персональный токен доступа](/docs/dbt-apis/user-tokens). Обязательно скопируйте токен. 

Вы можете использовать созданный персональный токен доступа (PAT) для аутентификации при работе с [API](/docs/dbt-apis/sl-api-overview) и [интеграциями](/docs/platform-integrations/avail-sl-integrations) <Constant name="semantic_layer" />.

### 3. Просмотрите сведения о подключении {#3-view-connection-detail}
1. Вернитесь на страницу **Project details**, чтобы посмотреть параметры подключения для downstream‑инструментов.
2. Скопируйте и передайте соответствующим командам Environment ID, service или personal token, Host, а также имя service или personal token для настройки подключения BI‑инструментов. Если ваш инструмент использует GraphQL API, сохраните информацию о GraphQL API host вместо JDBC URL.

Информацию о подключении к другим интеграциям см. в разделе [Доступные интеграции](/docs/platform-integrations/avail-sl-integrations).

<Lightbox src="/img/docs/dbt-platform/semantic-layer/sl-configure-example.png" width="50%" title="После настройки вы получите параметры подключения к инструментам, использующим данные семантического слоя." />

### 4. Добавьте дополнительные учетные данные <Lifecycle status="managed_plus,managed" /> {#4-add-more-credentials}
Во всех планах <Constant name="dbt" /> Enterprise можно при необходимости добавить несколько наборов учетных данных и сопоставить их с сервисными токенами. Это позволяет более детально управлять доступом и настраивать его для разных команд. Затем эти учетные данные можно передать соответствующим командам для настройки подключения BI-инструментов. Эти учетные данные управляют физическим доступом к базовым данным, к которым обращается семантический слой.

Мы рекомендуем настраивать учетные данные и сервисные токены в соответствии с вашими командами и их ролями. Например, создавайте токены или учетные данные, которые соответствуют потребностям вашей команды, например, предоставляя доступ к схемам, связанным с финансами, для финансовой команды.

<Expandable alt_header="Соображения по связыванию учетных данных">

- Администраторы могут связывать несколько сервисных токенов с одними учетными данными в проекте, но каждый сервисный токен может быть связан только с одними учетными данными на проект.
- Когда вы отправляете запрос через API, сервисный токен связанного учетного данных будет следовать политикам доступа к представлениям и таблицам, используемым для построения ваших запросов семантического слоя.
- <SLEnvVars/>
</Expandable>

#### 1. Добавьте дополнительные учетные данные
- После настройки окружения на странице **Credentials & service tokens** нажмите кнопку **Add Semantic Layer credential**, чтобы создать несколько наборов учетных данных и сопоставить их с сервисным токеном. <br />
- В разделе **1. Add credentials** заполните поля учетных данных платформы данных. Рекомендуем использовать учетные данные с доступом «только для чтения».
   <Lightbox src="/img/docs/dbt-platform/semantic-layer/sl-add-credential.png" width="55%" title="Добавьте учетные данные и сопоставьте их с сервисным токеном. " />

#### 2. Сопоставьте сервисные токены с учетными данными
- В разделе **2. Map new service token** [сопоставьте сервисный токен с учетными данными](/docs/use-dbt-semantic-layer/setup-sl#manage-from-service-token-page), настроенными на предыдущем шаге. <Constant name="dbt" /> автоматически выбирает необходимый набор разрешений для сервисного токена (Semantic Layer Only и Metadata Only).
- Чтобы добавить еще один сервисный токен во время настройки, нажмите **Add Service Token**. 
- Позже вы сможете связать дополнительные сервисные токены с теми же учетными данными на странице **Semantic Layer Configuration Details**. Чтобы добавить еще один сервисный токен в существующую конфигурацию Semantic Layer, нажмите **Add service token** в разделе **Linked service tokens**.
- Нажмите **Save**, чтобы связать сервисный токен с учетными данными. Не забудьте скопировать сервисный токен и сохранить его в безопасном месте: после создания просмотреть его повторно будет невозможно.
<Lightbox src="/img/docs/dbt-platform/semantic-layer/sl-credentials-service-token.png" width="90%" title="Используйте страницу настройки для управления несколькими наборами учетных данных, привязки и отвязки сервисных токенов, чтобы более точно управлять доступом."/>

#### 3. Удалите учетные данные {#3-delete-credentials}
- Чтобы удалить учетные данные, вернитесь на страницу **Учетные данные и сервисные токены**.
- В разделе **Связанные сервисные токены** нажмите **Редактировать** и выберите **Удалить учетные данные**, чтобы удалить учетные данные.

   Когда вы удаляете учетные данные, любые сервисные токены, связанные с этими учетными данными в проекте, перестанут работать и будут недоступны для конечных пользователей.

### Удаление конфигурации {#delete-configuration}
Вы можете удалить всю конфигурацию Semantic Layer для проекта. Обратите внимание, что удаление конфигурации Semantic Layer приведёт к удалению всех учётных данных и отвязке всех service token от проекта. Также это приведёт к тому, что все запросы к Semantic Layer будут завершаться с ошибкой.

Следуйте этим шагам, чтобы удалить конфигурацию Семантического слоя для проекта:

1. Перейдите на страницу **Детали проекта**.
2. В разделе **Семантический слой** выберите **Удалить Семантический слой**.
3. Подтвердите удаление, нажав **Да, удалить семантический слой** в всплывающем окне подтверждения.

Чтобы повторно включить настройку Семантического слоя dbt в будущем, вам нужно будет воссоздать ваши конфигурации, следуя [предыдущим шагам](#1-select-environment). Если ваши семантические модели и метрики все еще находятся в вашем проекте, никаких изменений не требуется. Если вы их удалили, вам нужно будет снова настроить конфигурации YAML.

## Дополнительная конфигурация {#additional-configuration}

 Следующие дополнительные гибкие конфигурации для учетных данных Семантического слоя.

### Сопоставление сервисных токенов с учётными данными
- После настройки окружения вы можете сопоставить дополнительные сервисные токены с теми же учётными данными, если у вас есть необходимые [разрешения](/docs/platform/manage-access/enterprise-permissions#permission-sets).
- Перейдите на страницу **Credentials & service tokens** и нажмите кнопку **+Add Service Token** в разделе **Linked Service Tokens**.
- Введите имя сервисного токена и выберите нужный набор разрешений (Semantic Layer Only и Metadata Only).
- Нажмите **Save**, чтобы связать сервисный токен с учётными данными.
- Не забудьте скопировать сервисный токен и сохранить его в безопасном месте, поскольку после создания он больше не будет доступен для просмотра.

<Lightbox src="/img/docs/dbt-platform/semantic-layer/sl-add-service-token.gif" title="Сопоставление дополнительных сервисных токенов с учётными данными." />

### Отвяжите сервисные токены {#unlink-service-tokens}
- Отвяжите сервисный токен от учетных данных, нажав **Отвязать** в разделе **Связанные сервисные токены**. Если вы попытаетесь выполнить запрос к Семантическому слою с отвязанными учетными данными, вы столкнетесь с ошибкой в вашем BI-инструменте, так как не будет сопоставлен действительный токен.

### Управление со страницы сервисных токенов {#manage-from-service-token-page}
**Просмотр учетных данных из сервисного токена**
- Просмотрите ваши учетные данные Семантического слоя напрямую, перейдя на страницу **API токены**, а затем **Сервисные токены**.
- Выберите сервисный токен, чтобы просмотреть учетные данные, с которыми он связан. Это полезно, если вы хотите узнать, какие сервисные токены сопоставлены с учетными данными в вашем проекте.

#### Создайте новый сервисный токен {#create-a-new-service-token}
- На странице **Сервисные токены** создайте новый сервисный токен и сопоставьте его с учетными данными (при условии, что разрешение на семантический слой существует). Это полезно, если вы хотите создать новый сервисный токен и напрямую сопоставить его с учетными данными в вашем проекте.
- Убедитесь, что выбрали правильный набор разрешений для сервисного токена (Только Семантический слой и Только метаданные).
