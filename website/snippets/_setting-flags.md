Существует несколько способов настройки флагов в зависимости от сценария использования:
- **[Параметры CLI](/reference/global-configs/command-line-options):** Определяют поведение для _конкретного вызова_. Поддерживаются для всех команд dbt.
- **[Переменные окружения](/reference/global-configs/environment-variable-configs):** Определяют различное поведение в разных средах выполнения (разработка, промышленная эксплуатация или [непрерывная интеграция](/docs/deploy/continuous-integration)) или для разных пользователей в среде разработки (на основе личных предпочтений).
- **[Флаги `flags` на уровне проекта в `dbt_project.yml`](/reference/global-configs/project-flags):** Определяют значения по умолчанию, хранящиеся в системе контроля версий, для всех, кто запускает этот проект. Также позволяют включать или отключать [изменения поведения](/reference/global-configs/behavior-changes), чтобы управлять переходом с устаревшей функциональности.
- **[Пользовательские настройки (`~/.dbt/user_settings.yml`)](/reference/global-configs/user-settings):** Определяют личные предпочтения, которые применяются ко всем проектам на вашем компьютере. Записываются автоматически командой `dbt login`.

Наиболее конкретная настройка имеет приоритет. Наивысший приоритет имеют параметры CLI, затем идут переменные окружения, далее — `dbt_project.yml` и, наконец, `user_settings.yml`. Если флаг не задан ни в одном из этих мест, используется значение по умолчанию, определённое в dbt.

```yaml
# dbt_project.yml
flags:
  # значение по умолчанию для запуска этого проекта — везде, всегда, для всех
  fail_fast: true
```
<VersionBlock lastVersion="1.10">

```bash
# установить эту переменную окружения в значение 'True' (синтаксис bash)
export DBT_FAIL_FAST=1
dbt run
```

</VersionBlock>

<VersionBlock firstVersion="1.11">

```bash
# установите для этой переменной окружения значение 'True' (синтаксис bash)
export DBT_ENGINE_FAIL_FAST=1
dbt run
```

</VersionBlock>
```bash
dbt run --fail-fast # установить True для этого конкретного запуска
dbt run --no-fail-fast # установить False
```

Есть две категории исключений:
1. **Флаги, задающие пути к файлам:** Флаги для путей к файлам, используемых во время выполнения (например, `--log-path` или `--state`), нельзя задавать в `dbt_project.yml`. Чтобы переопределить значения по умолчанию, передайте параметры CLI или задайте переменные окружения (<VersionBlock lastVersion="1.10">`DBT_LOG_PATH` и `DBT_STATE`</VersionBlock><VersionBlock firstVersion="1.11">`DBT_ENGINE_LOG_PATH` и `DBT_ENGINE_STATE`</VersionBlock>). Флаги, указывающие dbt, где искать ресурсы проекта (например, `model-paths`), задаются в `dbt_project.yml`, но в виде ключей верхнего уровня, вне словаря `flags`; эти настройки должны быть полностью статичными и никогда не меняться в зависимости от команды или среды выполнения.
2. **Флаги включения изменений поведения:** Флаги, включающие или отключающие [изменения поведения](/reference/global-configs/behavior-changes), можно задавать _только_ в `dbt_project.yml`. Предполагается, что они задаются в системе контроля версий и изменяются через запросы на слияние (pull/merge request). Их значения не должны оставаться различными для разных запусков, сред или пользователей в течение неопределённо долгого времени.
