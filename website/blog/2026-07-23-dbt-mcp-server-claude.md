Когда мы открыли исходный код MCP-сервера dbt в [апреле 2025 года](/blog/introducing-dbt-mcp-server), это был экспериментальный проект для локального запуска с чёткой идеей: структурированные данные будут глубоко интегрированы в рабочие процессы с ИИ, а dbt станет слоем, предоставляющим управляемый контекст, на котором эти процессы основаны. [Anthropic](https://claude.com/blog/how-anthropic-enables-self-service-data-analytics-with-claude) помогла подтвердить нашу гипотезу. Естественным следующим шагом стала облачная версия с удалённой аутентификацией через OAuth, чтобы вы могли использовать её с любым удобным для вас ИИ-инструментом.

Теперь удалённый MCP-сервер dbt работает внутри <Constant name="dbt_platform" />, и вы можете подключить его к Claude за одну-две минуты: достаточно войти в аккаунт и пройти аутентификацию. Вы добавляете dbt как коннектор, подтверждаете нужные права доступа, и Claude получает доступ к вашим управляемым данным и обширным метаданным dbt.

В этой статье мы рассмотрим, какие возможности удалённый сервер открывает в Claude, для каких рабочих процессов людей и агентов он подходит и как инструменты взаимодействуют, оказавшись в одном диалоге.

## Обзор всех возможностей

Сервер предоставляет набор инструментов для работы с вашим проектом dbt. Вы задаёте вопросы на естественном языке, а Claude выбирает подходящий инструмент для каждого запроса. Ниже перечислены инструменты, доступные на сегодняшний день. Полный список приведён в [документации по доступным инструментам](/docs/dbt-ai/mcp-available-tools?version=2.0).

| Возможность | О чём можно спросить | Примеры инструментов |
| ----- | ----- | ----- |
| Поиск и происхождение данных | Какие модели существуют, как они связаны, что содержит модель и в каком она состоянии | `get_all_models`, `get_model_details`, `get_lineage`, `get_model_health` |
| Управляемые метрики | Ответы на бизнес-вопросы на основе ваших сертифицированных определений в Semantic Layer | `list_metrics`, `get_dimensions`, `query_metrics` |
| Гибкая работа с SQL | Создание и выполнение исследовательских запросов с полным учётом ваших моделей | `text_to_sql`, `execute_sql` |
| Операционная работа | История запусков заданий, сведения об ошибках и повторные запуски через Administrative API | `list_jobs_runs`, `get_job_run_error`, `retry_job_run` |
| Происхождение данных на уровне столбцов | Отслеживание зависимостей вплоть до отдельного столбца с помощью <Constant name="fusion_engine" /> | `fusion.get_column_lineage` |
| Документация продукта | Ответы на вопросы о dbt из официальной документации | `search_product_docs`, `get_product_doc_pages` |

[dbt Semantic Layer](/docs/use-dbt-semantic-layer/dbt-sl) — основа этого списка и самая перспективная возможность с точки зрения пользы для нетехнических специалистов. Ваши метрики определены явно, поэтому, когда Claude отвечает на вопрос о выручке или активных пользователях, он возвращает достоверное значение. Все остальные инструменты формируют надёжный контекст вокруг этого управляемого ядра, и каждый из них одинаково полезен как человеку, задающему вопрос, так и агенту, выполняющему действие.

В этой короткой демонстрации я показываю, как использую MCP-сервер dbt, чтобы разобраться в возможностях и текущем состоянии своих данных, а затем отвечать на вопросы с учётом этого контекста.

Практически любому процессу полезен достоверный ответ на вопрос: «Что на самом деле происходит в бизнесе?» Для планирования кампании нужны показатели привлечения клиентов. Для постановки цели — исходный уровень. Для еженедельного отчёта — фактические показатели за прошлую неделю. Можно вернуться к дашборду, но такое переключение контекста даёт ещё один повод отвлечься и прерывает процесс принятия решений.

Как только управляемый контекст вашего проекта dbt становится доступен внутри Claude, он превращается в основу, на которую опираются другие коннекторы. Внутренние знания, так называемый «контекст», системы управления проектами и инструменты наблюдаемости становятся полезнее, когда рядом с ними есть достоверные данные. dbt предоставляет ключевой элемент, вокруг которого выстраивается остальная работа.

## Контекст dbt в повседневных рабочих процессах

Настоящая польза проявляется, когда вы включаете структурированные данные dbt и их контекст в уже привычные рабочие процессы. Вот три примера использования контекста проекта dbt вместе с другими инструментами.

### 1. Разработка маркетинговой кампании

Когда-то я работал в маркетинге. Как начинающий аналитик данных, я хотел принимать как можно больше решений на основе данных. Однако ограничения тогдашних инструментов делали полноценный анализ и планирование слишком трудоёмкими, поэтому приходилось полагаться на чутьё и опыт. Теперь вы можете собрать нужные данные из CRM, платной рекламы, органического продвижения в соцсетях и вебинаров в хранилище с управляемыми метриками. Вы можете дополнить свой контекст, чутьё и опыт помощью аналитика, который отлично ориентируется в данных. Пытаться собрать целостную картину по нескольким дашбордам, где доступно лишь несколько уровней детализации, — не лучшее применение времени. Вместо этого можно получать нужные данные с необходимой глубиной детализации и при этом сосредоточиться на формулировке сообщений, охвате аудитории и экспериментах для достижения результатов.

Целевые показатели и регулярные отчёты опираются на одни и те же управляемые метрики, поэтому сервер естественным образом подходит для таких задач. Ставьте квартальные цели на основе исходных показателей из Semantic Layer и фиксируйте их в Google Sheets или Notion. Затем с удобной вам периодичностью поручайте Claude готовить бизнес-обзор, сравнивающий фактические показатели с целевыми, и публиковать его в канале Slack. Главное преимущество — возможность подробно разбирать цифры и вместе с Claude обсуждать возможные интерпретации и стратегии. Вы приходите на встречу, владея информацией, подготовившись к уточняющим вопросам и имея наготове решения.

### 3. Управление платформой данных

Этот сценарий ближе всего инженерам-аналитикам. Большую часть времени мы поддерживаем платформу, а не обязательно создаём совершенно новые модели, и ИИ наиболее полезен в сочетании с другими инструментами для работы с данными. Используйте инструменты dbt для поиска моделей, проверки их состояния и отслеживания происхождения данных, а также инструменты Administrative API вместе с коннектором наблюдаемости, например Datadog, и инструментом управления инцидентами, например incident.io. Если задание завершается с ошибкой или дашборд выглядит подозрительно, Claude сопоставляет ошибку запуска dbt и неуспешный тест с сигналами инфраструктуры, определяет масштаб влияния по зависимостям данных и составляет сводку инцидента — всё в одном месте.

_Ещё один сценарий, который стоит попробовать: безопасное управление изменениями._ Прежде чем переименовывать или удалять столбец, объедините `fusion.get_column_lineage` и `get_model_details` с вашей системой отслеживания задач в Linear, Jira или GitHub. Claude проследит все нижестоящие модели, объекты exposure и дашборды, зависящие от этого поля, а затем заведёт задачи или создаст контрольный список для проверки, чтобы при внесении изменения весь масштаб его влияния был известен. Было бы упущением не отметить, что это идеальный сценарий для [Wizard](/docs/platform/wizard-overview).

## Начало работы

Подробные инструкции по настройке приведены в разделе [Интеграция с Claude](/docs/dbt-ai/integrate-mcp-claude?version=2.0&name=Fusion).

1. В <Constant name="dbt_platform" /> скопируйте URL вашей конечной точки MCP из раздела **Account settings** → **Access URLs** → **MCP Endpoint URL**.
2. В Claude Desktop или веб-приложении Claude откройте настройки коннекторов, добавьте пользовательский коннектор, вставьте URL и нажмите **Connect**. Claude перенаправит вас в dbt для входа и покажет экран согласия, где вы подтвердите, какие разрешения хотите предоставить.
3. В Claude Code добавьте сервер в `.mcp.json` в корне проекта, чтобы вся команда использовала эту настройку:

   ```json
   {
     "mcpServers": {
       "dbt": {
         "type": "http",
         "url": "https://YOUR_DBT_HOST_URL/api/ai/v1/mcp/"
       }
     }
   }
   ```

4. Задайте вопрос к Semantic Layer, например: «Какова общая выручка за последние 30 дней в разбивке по регионам?», чтобы проверить подключение.

Для использования OAuth нужен аккаунт со статическим поддоменом — это часть `abc123` в адресе `abc123.us1.dbt.com`. Доступность зависит от вашего тарифного плана, поскольку удалённая аутентификация через OAuth внедряется на разных тарифах постепенно. Для клиентов, которые пока не поддерживают OAuth, доступна аутентификация по токену. Внимательно прочитайте экран согласия: разрешения позволяют предоставить Claude ровно тот доступ, который нужен конкретному рабочему процессу.

## Куда мы движемся

В апреле 2025 года мы говорили, что команды по работе с данными будут всё больше сосредотачиваться на создании обширного управляемого контекста для ИИ-систем, а dbt станет уровнем управления этим контекстом. Удалённый сервер с аутентификацией и нативной интеграцией в Claude — шаг к воплощению этой идеи в реальность. Управляемые определения, которые вы создаёте в dbt, теперь поступают напрямую в повседневные рабочие процессы — от маркетингового брифа до разбора инцидента, — а люди и агенты работают на одной и той же надёжной основе.

Это только начало, и лучшие практики предложит сообщество. Скопируйте URL вашей конечной точки MCP, добавьте dbt как пользовательский коннектор в Claude и начните с вопроса к Semantic Layer. Посмотрите, как много инструменты могут сделать вместе.

Присоединяйтесь к обсуждению в канале `#tools-dbt-mcp` в Slack сообщества dbt.
