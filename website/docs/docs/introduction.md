## Движок dbt

Текущее поколение dbt написано на Rust и изначально поддерживает анализ SQL на различных диалектах движков. Это позволяет dbt выявлять ошибки до того, как они попадут в ваше хранилище данных, и обеспечивает такие возможности редактора, как автодополнение и отображение ошибок прямо в коде по мере ввода.

При [установке dbt](/docs/local/install-dbt) по умолчанию используется v2. Эта версия опирается на среду выполнения фреймворка dbt с интерфейсом командной строки (CLI) и открытым исходным кодом под лицензией Apache 2.0. dbt можно использовать бесплатно, а некоторые возможности на базе платформы dbt становятся доступны при входе с любой учетной записью <Constant name="dbt_platform" />.

### Улучшите рабочие процессы разработки

Разработчикам dbt позволяет:

- Мгновенно выявлять некорректный SQL в моделях dbt, еще до их выполнения в хранилище данных
- Пользоваться автодополнением, подсказками при наведении и отображением ошибок прямо в коде по мере ввода
- Просматривать результаты <Term id="cte">CTE</Term> прямо в редакторе для ускорения отладки
- Отслеживать определения моделей и столбцов по всему проекту

Все это доступно бесплатно в [расширении dbt для VS Code](/docs/about-dbt-extension), созданном для раскрытия возможностей v2, но также доступном и в v1.

### Платформа dbt {#dbt-platform}

<Constant name="dbt_platform" /> — самый быстрый способ начать работать с dbt: планирование запусков, CI/CD, размещение документации, мониторинг и оповещения собраны в одном месте. Платформа работает как с v1, так и с v2 на всех тарифах — от Developer (бесплатного) до Enterprise+.

Разрабатывайте непосредственно на платформе с помощью [Studio IDE](/docs/platform/studio-ide/develop-in-studio) или подключайтесь с локального компьютера через расширение dbt для VS Code или <Constant name="platform_cli" />. 

Узнайте больше о [возможностях платформы dbt](/docs/platform/about-platform/dbt-platform-features), изучите [тарифы и цены](https://www.getdbt.com/pricing/) или попробуйте [руководство по быстрому старту](/guides).


### Локальная разработка с dbt {#dbt-local-development}

[Установите dbt](/docs/local/install-dbt), чтобы запускать v2 локально из командной строки на базе среды выполнения с открытым исходным кодом.

Для наиболее удобной разработки рекомендуем использовать v2 вместе с [расширением dbt для VS Code](/docs/about-dbt-extension), которое обеспечивает автодополнение, отображение ошибок прямо в коде и просмотр связей между данными во время работы. Вы также можете выполнить [`dbt login`](/reference/commands/login?version=2.0), чтобы получить доступ к возможностям на базе платформы dbt и создать бесплатную учетную запись <Constant name="dbt_platform" />.

Чтобы быстро начать работу, воспользуйтесь [руководством по быстрому старту с dbt](/guides/dbt).

Другие способы запуска dbt в собственной инфраструктуре:
- [<Constant name="core_v1" />](/docs/local/install-dbt?version=1.0): исходный CLI на Python. 
- [dbt OSS](/docs/local/install-dbt-v2): бесплатный дистрибутив нового движка dbt на Rust с полностью открытым исходным кодом (Apache 2.0). Обычно предназначен для организаций со строгими требованиями к использованию именно этой среды выполнения с открытым исходным кодом.

Чтобы внести вклад в проект с открытым исходным кодом, обратитесь к [репозиторию на GitHub](https://github.com/dbt-labs/dbt).

## Зачем использовать dbt

При работе с dbt вы в основном сосредоточитесь на написании моделей (запросов select), отражающих ключевую бизнес-логику, — вам не придется писать шаблонный код для создания таблиц и представлений или определять порядок выполнения моделей. Вместо этого dbt сам преобразует эти модели в объекты вашего хранилища данных.

- **Без шаблонного кода**: описывайте бизнес-логику с помощью одного SQL-выражения `select` или DataFrame на Python. dbt берет на себя <Term id="materialization" />, транзакции, <Term id="ddl" /> и изменения схемы.
- **Модульность и повторное использование**: создавайте модели данных, на которые можно ссылаться в дальнейшей работе. Измените модель один раз, и изменение распространится на все зависящие от нее модели, позволяя публиковать единую эталонную бизнес-логику без повторной реализации.
- **Быстрые сборки**: используйте [инкрементальные модели](/docs/build/incremental-models) и метаданные для оптимизации моделей с длительным временем выполнения.
- **Тестирование и документация** &mdash; Пишите [тесты качества данных](/docs/build/data-tests) для исходных данных и автоматически создавайте [документацию](/docs/build/documentation) вместе с кодом.
- **Практики разработки ПО**: контроль версий, ветвление, пул-реквесты, CI/CD и [управление пакетами](/docs/build/packages) для ваших конвейеров данных. Пишите код, лучше соответствующий принципу <Term id="dry" />, с помощью [макросов](/docs/build/jinja-macros) и [хуков](/docs/build/hooks-operations).
- **Разработка с помощью ИИ**: используйте [<Constant name="wizard" />](/docs/platform/wizard-overview), чтобы исследовать, создавать, проверять и выпускать решения с помощью естественного языка. <Constant name="wizard" /> опирается на полный контекст вашего проекта, проверяет результаты своей работы с учетом связей между данными и тестов, а также по умолчанию включает средства управления и журналы аудита.
