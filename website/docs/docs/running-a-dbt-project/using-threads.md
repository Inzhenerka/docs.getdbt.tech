При запуске dbt создает направленный ациклический граф (DAG) связей между моделями. Количество потоков определяет максимальное число путей в графе, которые dbt может обрабатывать одновременно: увеличение количества потоков может сократить время выполнения вашего проекта.

Например, если указать `threads: 1`, dbt начнет построение только одной модели и завершит его, прежде чем перейти к следующей. Значение `threads: 4` означает, что dbt будет работать одновременно _не более чем с_ 4 моделями, не нарушая зависимостей; фактическое количество моделей, с которыми он сможет работать одновременно, скорее всего, будет ограничено доступными путями в графе зависимостей.

Ниже показана разница между выполнением проекта с 1 потоком и 4 потоками. При использовании 1 потока dbt строит по одной модели за раз в порядке зависимостей. При использовании 4 потоков dbt параллельно строит столько готовых к построению моделей, сколько позволяет граф, и завершает работу значительно быстрее. 

<Lightbox src="/img/docs/running-a-dbt-project/threads-1-vs-4-animated.gif" title="Увеличьте количество потоков, чтобы выполнять построение параллельно и завершать работу быстрее. Цвета имеют разные значения: серый — ожидание, оранжевый — построение, зеленый — завершено." />

Жёсткого ограничения на максимальное количество потоков, которое вы можете задать, не существует — в целом увеличение числа потоков сокращает время выполнения, однако при этом важно учитывать несколько факторов:

Как правило, оптимальное количество потоков зависит от вашего хранилища данных и его конфигурации. Лучше всего протестировать разные значения, чтобы найти оптимальное количество потоков для вашего проекта. 

<VersionBlock lastVersion="1.99">

В dbt v1 рекомендуем для начала установить значение 4.

</VersionBlock>

<VersionBlock firstVersion="2.0">

В dbt v2 начните с максимального значения и при необходимости уменьшайте его. Рекомендуемые значения приведены в разделе [Оптимизация потоков в dbt v2](#dbt-v2-thread-optimization).

</VersionBlock>

Вы можете использовать количество потоков, отличное от значения, заданного в вашей целевой конфигурации (target), указав параметр `--threads` при выполнении команды dbt.

Количество потоков задаётся в файле `profiles.yml` (при локальной разработке с <Constant name="core" /> и <Constant name="fusion_engine" />), в настройках задания <Constant name="dbt" /> и в учётных данных для разработки <Constant name="dbt" /> в вашем профиле.


## Оптимизация потоков в <Constant name="fusion_engine" /> {#dbt-v2-thread-optimization}

В контексте <Constant name="fusion"/> поток — это открытое соединение с вашим хранилищем данных, а не количество параллельных потоков процессора вашего локального компьютера. Платформы данных различаются по количеству допустимых одновременных соединений; при превышении этих ограничений платформа отклоняет новые соединения.

В dbt v2 параметр `threads` задаёт максимальное количество SQL-запросов, которые dbt одновременно выполняет в вашем хранилище данных. Чтобы dbt v2 мог выполнять одновременно столько запросов, сколько позволяет ваш проект:

- **При запуске в <Constant name="dbt_platform"/>**: установите для `threads` значение `256` в [настройках задания](/docs/deploy/deploy-jobs?version=2#create-and-schedule-jobs).
- **При локальном запуске**: укажите `threads: 0` (или передайте `--threads 0`).

Если ваше хранилище данных отклоняет соединения или вы достигаете ограничений частоты запросов, уменьшите значение `threads`, чтобы снизить нагрузку от одновременных запросов.

Разбор проекта выполняется отдельно и автоматически использует все доступные процессоры. Чтобы отключить параллельный разбор и выполнять операции по одной, используйте флаг `--no-parallel`. Это полезно для отладки ошибок разбора и не влияет на `threads`.
