Объект models позволяет запрашивать информацию обо всех моделях в рамках конкретного job.

### Аргументы {#arguments}

При выполнении запроса к `models` доступны следующие аргументы.

<NodeArgsTable parent="JobNode" name="models" />

Ниже приведены примеры запросов и описание схемы объекта models.

### Примеры запросов {#example-queries}
Аргументы database, schema и identifier являются необязательными. Это означает, что с помощью данного эндпоинта вы можете:

- Найти конкретную модель, указав `<database>.<schema>.<identifier>`
- Найти все модели в базе данных и/или схеме, указав `<database>` и/или `<schema>`

#### Поиск моделей по базе данных, схеме и идентификатору {#find-models-by-their-database-schema-and-identifier}
В примере ниже показан запрос, который находит модель по её уникальной базе данных, схеме и идентификатору.

```graphql
{
  job(id: 123) {
    models(
      database: "analytics"
      schema: "analytics"
      identifier: "dim_customers"
      first: 10
      after: "{somePaginationCursorValue}"
    ) {
      uniqueId
      paginationCursor
    }
  }
}
```

#### Поиск моделей по схеме {#find-models-by-their-schema}
В примере ниже показан запрос, который находит все модели в данной схеме и их соответствующее время выполнения.

```graphql
{
  job(id: 123) {
    models(schema: "analytics", first: 10, after: "{somePaginationCursorValue}") {
      uniqueId
      executionTime
      paginationCursor
    }
  }
}
```

#### Постраничная выборка моделей в запуске задания

Запросы `models` на уровне задания поддерживают `first` и `after` для пагинации на основе курсора. Для каждой модели возвращается поле `paginationCursor`, позволяющее получить следующую страницу. Сведения о поведении пагинации, поддерживаемых типах ресурсов и прежнем поведении по умолчанию см. в разделе [Запросы на уровне задания](/docs/dbt-apis/discovery-querying#job-based-queries).

```graphql
query JobModelsPage($jobId: BigInt!, $runId: BigInt, $first: Int!, $after: String) {
  job(id: $jobId, runId: $runId) {
    models(first: $first, after: $after) {
      uniqueId
      executionTime
      paginationCursor
    }
  }
}
```

### Поля {#fields}
Объект models предоставляет доступ к _тем же полям_, что и [узел Model](/docs/dbt-apis/discovery-schema-job-model). Разница в том, что объект models может возвращать список, поэтому вместо запроса полей одной конкретной модели можно запросить эти параметры для всех моделей в рамках jobID, базы данных и так далее.
