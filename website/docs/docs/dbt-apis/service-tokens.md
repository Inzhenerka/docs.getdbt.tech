# Токены сервисных аккаунтов

Токены сервисных аккаунтов позволяют безопасно проходить аутентификацию в API <Constant name="dbt" />: каждому токену назначается ограниченный набор разрешений для более точного управления доступом к API. Хотя они похожи на [персональные токены доступа](/docs/dbt-apis/user-tokens), токены сервисных аккаунтов принадлежат аккаунту, а не пользователю.

Токены сервисных аккаунтов можно использовать для интеграций на уровне системы, которые не выполняются от имени конкретного пользователя. Назначьте токену сервисного аккаунта любые наборы разрешений, доступные в <Constant name="dbt" />. Доступные наборы могут немного различаться в зависимости от вашего тарифного плана:

* Планы Enterprise и Enterprise+ могут применять к сервисным токенам любые доступные наборы разрешений.
* Планы Developer и Starter могут применять к сервисным токенам набор разрешений <Constant name="semantic_layer" />.
* Устаревшие планы Team (Legacy Team) могут применять к сервисным токенам наборы разрешений Account Admin, Member, Job Admin, Read-Only, Metadata и <Constant name="semantic_layer" />.

Одному токену можно назначить столько наборов разрешений, сколько необходимо. Подробнее о наборах разрешений см. в разделе «[Разрешения Enterprise](/docs/platform/manage-access/enterprise-permissions)».

## Генерация токенов сервисных аккаунтов {#generate-service-account-tokens}

Вы можете создавать сервисные токены, если у вас есть [лицензия](/docs/platform/manage-access/seats-and-users) Developer и [права](/docs/platform/manage-access/enterprise-permissions#permission-sets) администратора аккаунта. Чтобы создать сервисный токен в <Constant name="dbt" />, выполните следующие действия:

1. В <Constant name="dbt" /> нажмите на название своего аккаунта в меню слева и выберите **Account settings**.
2. На левой боковой панели нажмите **Service Tokens**.
3. Нажмите кнопку **+ Create service token**, чтобы создать новый токен.
    1. Введите имя токена. 
    2. Добавьте необходимые [права](/docs/dbt-apis/service-tokens#permissions-for-service-account-tokens).
4. После создания токена вы больше не сможете его просмотреть, поэтому обязательно сохраните его в безопасном месте.

## Разрешения для токенов сервисных аккаунтов {#permissions-for-service-account-tokens}

Токенам сервисных аккаунтов можно назначать любые наборы разрешений, доступные в <Constant name="dbt" />. При назначении набора разрешений токену вы также можете выбрать, будут ли эти разрешения действовать для всех проектов аккаунта или только для определённых проектов.

### Планы для команд, использующие токены сервисных аккаунтов {#team-plans-using-service-account-tokens}

Следующие разрешения можно назначить токену сервисного аккаунта на тарифном плане Team. Подробнее об этих ролях см. в разделе [Разрешения Enterprise](/docs/platform/manage-access/enterprise-permissions).

- Account Admin — сервисные токены Account Admin имеют полный доступ `read + write` ко всей учётной записи, поэтому используйте их с осторожностью. В плане Team этот набор прав называется ролью **"Owner role"**.
- Billing Admin
- Job Admin
- Metadata Only
- Member
- Read-only
- <Constant name="semantic_layer" /> Only

Подробнее об этих ролях см. в разделе [Разрешения Enterprise](/docs/platform/manage-access/enterprise-permissions).

## Обновление сервисных токенов {#service-token-update}

18 июля 2023 года dbt Labs изменила способ генерации и проверки токенов, чтобы повысить производительность. Эти улучшения применяются только к токенам, созданным после 18 июля 2023 года.

Старые токены остаются действительными, однако если они используются для высокочастотных вызовов API, мы рекомендуем выполнить их ротацию, чтобы снизить задержки.

Чтобы выполнить ротацию токена:

1. Перейдите в **Account settings** и нажмите **Service tokens** на левой боковой панели.
2. Убедитесь, что дата создания токена в поле **Created** — _18 июля 2023 года или ранее_.
3. Нажмите **+ New Token** в правом верхнем углу экрана. Убедитесь, что у нового токена те же разрешения, что и у старого.
4. Скопируйте новый токен и замените им старый в своих системах. Сохраните его в безопасном месте, поскольку после закрытия экрана создания токена он больше не будет доступен.
5. Удалите старый токен в <Constant name="dbt" />, нажав **значок корзины**. _Выполняйте это действие только после замены старого токена новым, чтобы избежать перебоев в работе сервисов_.
