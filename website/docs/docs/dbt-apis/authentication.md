## Типы токенов доступа к API {#types-of-api-access-tokens}

**Персональные токены доступа:** Предпочтительный и безопасный способ доступа к API <Constant name="dbt" /> от имени пользователя. Персональные токены доступа (PAT) действуют в пределах аккаунта и позволяют более детально настраивать права доступа и управлять ими. 

**Сервисные токены:** Сервисные токены аналогичны сервисным учетным записям и являются предпочтительным способом предоставления доступа от имени аккаунта <Constant name="dbt" />.

### Какой тип токена следует использовать {#which-token-type-should-you-use}

Используйте служебные токены для любых рабочих процессов в промышленной среде, которым требуется служебная учётная запись. Персональные токены доступа (PAT) следует использовать только для рабочих процессов разработки _или_ рабочих процессов клиентов <Constant name="dbt" />, которым требуется контекст пользователя. Следующие примеры показывают, когда следует использовать персональный токен доступа (PAT), а когда — служебный токен: 

* **Подключение партнёрской интеграции к <Constant name="dbt" />** &mdash; Примеры таких интеграций: [интеграция <Constant name="semantic_layer" /> с Google Sheets](/docs/platform-integrations/avail-sl-integrations), Hightouch, Datafold, созданное вами приложение и т. д. Для таких интеграций следует использовать служебный токен вместо PAT, поскольку служебные токены позволяют отслеживать их использование, ограничивать права доступа только тем, что необходимо интеграции, и соблюдать принцип минимальных привилегий. Если сейчас вы используете персональный токен доступа для этих интеграций, настоятельно рекомендуем перейти на служебный токен.
* **Terraform в промышленной среде** &mdash; Используйте служебный токен, поскольку это рабочий процесс в промышленной среде, выполняемый от имени служебной, а не пользовательской учётной записи. 
* **<Constant name="platform_cli" />** &mdash; Используйте PAT, поскольку <Constant name="platform_cli" /> работает в контексте пользователя (запросы выполняет пользователь, и он должен действовать в рамках своей учётной записи).
* **Тестирование пользовательского скрипта и работа с Terraform или Postman в тестовой среде** &mdash; Рекомендуем использовать PAT, поскольку это рабочий процесс разработки, ограниченный правами пользователя, который вносит изменения. При переносе этого скрипта или Terraform в промышленную среду используйте служебный токен.
* **Конечные точки API, которым требуется контекст пользователя** &mdash; Используйте PAT для аутентификации при обращении к любой конечной точке API, которой требуется контекст пользователя (например, к конечным точкам для создания и обновления учётных данных пользователей).
