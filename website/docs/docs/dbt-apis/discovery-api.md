# О Discovery API

При каждом запуске проекта <Constant name="dbt" /> генерирует и сохраняет информацию о нём. Эти метаданные содержат сведения о моделях, источниках и других узлах проекта, а также результаты их выполнения. С помощью Discovery API в <Constant name="dbt" /> вы можете запрашивать эту подробную информацию, чтобы лучше понимать свой <Term id="dag">DAG</Term> и данные, которые он формирует.

Используя метаданные в <Constant name="dbt" />, вы можете создавать системы мониторинга данных и оповещений, исследования происхождения данных и автоматизированной отчётности. Это поможет вам улучшить поиск данных, их качество и работу конвейеров в вашей организации.

Вы можете обращаться к Discovery API с помощью [разовых запросов](/docs/dbt-apis/discovery-querying), собственных приложений, широкого набора [интеграций партнёрской экосистемы](https://www.getdbt.com/product/integrations/) (например, для BI и аналитики, каталогизации и управления данными, контроля качества и наблюдаемости), а также используя такие возможности <Constant name="dbt" />, как [статистика времени выполнения моделей](/docs/deploy/run-visibility#model-timing-tab) и [плитки состояния данных](/docs/explore/data-tile).

Вы можете запрашивать метаданные <Constant name="dbt" />:

- На уровне [окружения](/docs/environments-in-dbt) — как для получения последнего состояния (используйте эндпоинт `environment`), так и для получения исторических результатов запусков (используйте `modelHistoricalRuns`) проекта <Constant name="dbt" /> в рабочей среде.
- На уровне задания — для получения результатов конкретного запуска задания <Constant name="dbt" /> для заданного типа ресурса, например `models` или `test`.

## Для чего можно использовать Discovery API {#what-you-can-use-the-discovery-api-for}

Нажмите на следующие вкладки, чтобы узнать больше о случаях использования API, анализе, который вы можете провести, и результатах, которых вы можете достичь, интегрировав его.

Чтобы использовать API напрямую или интегрировать с ним свой инструмент, обратитесь к разделу [Сценарии использования и примеры](/docs/dbt-apis/discovery-use-cases-and-examples), где приведена подробная информация.

<TabItem value="performance" label="Производительность">

Используйте API для анализа исторических данных, таких как время сборки моделей, чтобы оценить состояние ваших проектов dbt. Выявление неэффективных настроек оркестрации может помочь снизить затраты на инфраструктуру и обеспечить более своевременное выполнение задач. Подробнее о том, как это сделать, см. в разделе [Производительность](/docs/dbt-apis/discovery-use-cases-and-examples#performance).

Например, вы можете использовать вкладку [времени выполнения моделей](/docs/deploy/run-visibility#model-timing-tab), чтобы выявить и устранить узкие места при сборке моделей:

<Lightbox src="/img/docs/dbt-platform/discovery-api/model-timing.png" width="200%" title="Визуализация времени выполнения моделей в dbt"/>

</TabItem>

<TabItem value="quality" label="Качество">

Используйте API, чтобы определять точность и актуальность данных, отслеживая сбои тестов, свежесть источников и статус запусков. Точная и надежная информация важна для аналитики, принятия решений и мониторинга и помогает вашей организации избегать ошибочных решений. Подробнее об этом см. в разделе [Качество](/docs/dbt-apis/discovery-use-cases-and-examples#quality).

При использовании с [вебхуками](/docs/deploy/webhooks) это также может помочь в обнаружении, расследовании и оповещении о проблемах.

</TabItem>

<TabItem value="discovery" label="Обнаружение">

Используйте API, чтобы находить и изучать ресурсы dbt в интегрированных инструментах на основе определений моделей и метрик, а также информации о столбцах. Подробнее см. в разделе [Discovery](/docs/dbt-apis/discovery-use-cases-and-examples#discovery).

Производители данных должны управлять и организовывать данные для заинтересованных сторон, в то время как потребители данных должны быстро и уверенно анализировать данные в большом масштабе, чтобы принимать обоснованные решения, которые улучшают бизнес-результаты и снижают организационные издержки. API полезен для обнаружения данных в каталогах, аналитических приложениях и инструментах машинного обучения (ML). Он может помочь вам понять происхождение и значение наборов данных для вашего анализа.

Результаты анализа помогут вам понять, как создавать и развивать более эффективные проекты dbt. Подробнее см. в разделе [Разработка](/docs/dbt-apis/discovery-use-cases-and-examples#development).

## Типы состояния проекта {#types-of-project-state}

На уровне окружения можно запрашивать эти два типа [состояния проекта](/docs/dbt-apis/project-state):

- **Определение** &mdash; Логическое состояние [ресурсов](/docs/build/projects) проекта dbt, которое обновляется при изменении проекта.
- **Примененное** &mdash; Результат успешного выполнения DAG dbt, который создает или описывает состояние базы данных (например: `dbt run`, `dbt test`, свежесть источников и так далее).

Эти состояния позволяют вам легко изучать разницу между определением модели и ее примененным состоянием, чтобы вы могли получить ответы на такие вопросы, как: была ли выполнена модель? или выполнение не удалось? Примененные модели существуют как таблица/представление в платформе данных после их последнего успешного выполнения.
