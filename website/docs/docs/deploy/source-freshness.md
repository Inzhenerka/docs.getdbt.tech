<Constant name="dbt" /> предоставляет удобный интерфейс для работы с результатами [проверки свежести исходных данных](/docs/build/sources#source-data-freshness) в dbt. Если задание в <Constant name="dbt" /> настроено на выполнение проверок свежести источников, <Constant name="dbt" /> отображает пользовательский интерфейс с результатами последней проверки. Этот интерфейс помогает определить, соответствует ли свежесть исходных данных соглашению об уровне обслуживания (SLA), установленному в вашей организации.

### Включение проверок свежести источников {#enabling-source-freshness-checks}

[`dbt build`](/reference/commands/build) _не_ включает проверки свежести источников при сборке и тестировании ресурсов в вашем DAG. Вместо этого при настройке заданий можно использовать следующие распространённые подходы:
- Добавьте `dbt build` в шаг выполнения для запуска моделей, тестов и так далее. 
- <VersionBlock lastVersion="1.99">Установите флажок **Generate docs on run**, чтобы автоматически [создавать документацию проекта](/docs/explore/build-and-view-your-docs).</VersionBlock><VersionBlock firstVersion="2.0">При каждом запуске задания метаданные [<Constant name="catalog" />](/docs/explore/build-and-view-your-docs) обновляются автоматически, поэтому отдельный шаг для документации не нужен.</VersionBlock>
- Установите флажок **Run source freshness**, чтобы включить [проверку свежести источников](#checkbox) в качестве первого шага задания. 

<VersionBlock lastVersion="1.99">
<Lightbox src="/img/docs/dbt-platform/select-source-freshness.png" title="Выбор проверки свежести источников"/>
</VersionBlock>
  
Чтобы включить проверки свежести источников, сначала убедитесь, что для ваших источников настроены [параметры свежести](/docs/build/sources#source-data-freshness). Вы можете добавить проверку свежести источников в список команд в шагах выполнения задания или установить соответствующий флажок. Однако результат настройки задания с помощью флажка **Run source freshness** будет отличаться от результата добавления команды в шаги выполнения.

Чтобы включить снимки актуальности источников, сначала убедитесь, что ваши источники настроены для [снимка информации об актуальности](/docs/build/sources#source-data-freshness). Вы можете добавить актуальность источников в список команд на этапах выполнения задачи или включить флажок. Однако вы можете ожидать разные результаты при настройке задачи, выбрав флажок **Run source freshness** по сравнению с добавлением команды в этапы выполнения.

Рассмотрите следующие варианты и результаты:

| Варианты | Результаты |
|--------| ------- |
|  **Установить флажок <a id="checkbox"></a>** | Флажок **Run source freshness** в разделе **Execution Settings** запускает `dbt source freshness` первым шагом задания, и сбой этого шага не препятствует выполнению последующих шагов. Если вы хотите, чтобы задание было предназначено *исключительно* для проверки актуальности источников, всё равно необходимо добавить хотя бы один шаг-заглушку, например `dbt compile`. |
| **Добавить как шаг выполнения** | Добавьте команду `dbt source freshness` в любое место списка шагов выполнения задания. Однако, если данные в источнике устарели, этот шаг завершится с ошибкой, а последующие шаги не будут выполнены. <Constant name="dbt" /> отправит уведомления по электронной почте (если они настроены) в зависимости от итогового состояния этого шага. <br /><br /> Вы можете создать новое задание для проверки актуальности источников. <br /><br /> Если вы *не хотите*, чтобы ваши модели запускались при устаревших данных в источнике, имеет смысл запускать `dbt source freshness` первым шагом задания. В противном случае рекомендуем добавить `dbt source freshness` последним шагом задания или создать отдельное задание только для этой задачи.  |

### Частота проверки актуальности источников {#source-freshness-check-frequency}
Важно, чтобы задания проверки актуальности выполнялись достаточно часто для измерения задержки данных в соответствии с вашими SLA. Например, если для определённого набора данных установлен SLA в 1 час, проверять актуальность этой таблицы (<Term id="table" />) раз в день было бы нецелесообразно. Как правило, задания проверки актуальности источников следует запускать как минимум вдвое чаще, чем предусмотрено вашим самым коротким SLA. Ниже приведена таблица с примерами подходящей частоты проверок для типичных SLA:

| SLA | Частота проверки |
| --- | ------------------ |
| 1 час | 30 минут |
| 1 день | 12 часов |
| 1 неделя | Около одного раза в день |
