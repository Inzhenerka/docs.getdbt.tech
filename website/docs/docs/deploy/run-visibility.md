Вы можете просматривать историю запусков и панель мониторинга времени выполнения моделей, чтобы определить, какие аспекты заданий можно улучшить.

## История запусков {#run-history}

Панель **Run history** в <Constant name="dbt" /> помогает отслеживать состояние вашего проекта dbt. Она предоставляет подробный обзор всех запусков заданий проекта и различные фильтры, позволяющие сосредоточиться на отдельных аспектах. Вы также можете использовать её для просмотра недавних запусков, поиска запусков с ошибками и отслеживания хода выполняющихся запусков. Чтобы открыть панель, в верхнем меню навигации нажмите **Deploy**, а затем **Run history**.


Разработчики <Constant name="dbt" /> могут просматривать историю запусков за последние 365 дней через пользовательский интерфейс (UI) и API <Constant name="dbt" />.

dbt Labs ограничивает самостоятельное получение метаданных истории запусков периодом в 365 дней, чтобы повысить производительность <Constant name="dbt" />.

## Сведения о запуске задания {#job-run-details}

На дашборде **Run history** выберите конкретный запуск, чтобы просмотреть полную информацию о нём. Страница с деталями запуска задания показывает триггер задания, commit SHA, время ожидания в очереди планировщика, все шаги выполнения и их [логи](#access-logs), [время выполнения моделей](#model-timing-tab) и другую информацию.

Нажмите **Rerun now**, чтобы немедленно перезапустить задание.

### Вкладка Run summary {#run-summary-tab}

Вы можете просматривать и скачивать текущие и исторические логи запусков dbt. Это помогает эффективнее выявлять и устранять ошибки.

Для выполняющихся шагов <Constant name="dbt_platform" /> отображает только конец вывода логов &mdash; не более последних 1 000 строк или 0,5 МБ, в зависимости от того, какой предел достигнут раньше. Это относится как к консольным, так и к отладочным логам.
- Если логи обрезаны, в их верхней части появляется уведомление. Поскольку отображается только конец вывода, ресурс, который ещё выполняется, может не появляться в логах, пока его выполнение не завершится и его вывод не попадёт в отображаемую часть.
- После завершения шага доступен полный лог. 

<VersionBlock lastVersion="1.99">

Когда задание на <Constant name="core" /> завершается, при выборе шага открываются **System logs** (системные логи). В верхней части отображается сводка с количеством ошибок, предупреждений, уведомлений об устаревании, пропусков и успешных выполнений в выводе этого шага.

<Lightbox src="/img/docs/dbt-platform/deployment/system-logs.png" width="80%" title="Сводка системных логов" />

:::note
Значения счётчиков в системных логах определяются путём поиска совпадений с регулярными выражениями в тексте логов. Поэтому количество ошибок или предупреждений может превышать количество узлов с ошибками или предупреждениями.

Чтобы проверить фактическое количество, используйте кнопки со стрелками вверх и вниз рядом с каждым статусом для перехода к соответствующим строкам.
:::

</VersionBlock>

<VersionBlock firstVersion="2.0">

Когда задание на <Constant name="fusion_engine" /> завершается, при выборе шага открывается представление структурированных логов со статусом каждого ресурса. Узлы распределяются по следующим категориям; каждый узел можно развернуть, чтобы просмотреть подробные логи:
- **Success** (успешно)
- **Reused** (повторно использован)
- **Failed** (ошибка)
- **Warning** (предупреждение)
- **Running** (выполняется)
- **Skipped** (пропущен)
- **No-op** (без действий)

Подробнее о каждом статусе см. в разделе [Телеметрия и наблюдаемость в dbt v2](/reference/telemetry-observability#node-outcome).

#### Скачивание логов {#access-logs}

- Чтобы скачать логи отдельного шага, выберите его на вкладке **Run summary** и нажмите **Download** > **Download logs**. 
- Обратите внимание: при просмотре отладочных логов вывод обрезается. Чтобы просмотреть и экспортировать все отладочные логи отдельного шага, нажмите **Download** > **Download all debug logs**.


- Вы можете скачать логи OpenTelemetry (OTel) для шагов команд задания на <Constant name="fusion" /> в виде файла Parquet. Файл содержит структурированные данные логов на уровне шага, к которым можно выполнять запросы или которые можно анализировать вне dbt.

Чтобы скачать файл, перейдите на вкладку **Run summary** в задании, выберите шаг и нажмите **Download** > **Download OTel log** для экспорта файла Parquet

Этот пункт появляется только в том случае, если шаг создал артефакт лога OTel. Некоторые шаги, например `dbt deps`, не создают такой артефакт. Примеры анализа см. в разделе [Запросы к данным телеметрии](/reference/telemetry-observability#querying-telemetry-data).

#### Ограничения размера логов {#log-size-limits}

dbt ограничивает совокупный размер логов для конечных точек запусков. Если размер логов отдельного шага или общий размер логов запуска превышает этот предел, dbt не отображает логи.

Когда dbt не отображает логи из-за их размера, появляется баннер **Run logs are too large**, а на месте логов выводится соответствующее сообщение. Для шага запуска также отображается статус **Unknown**.

Вы по-прежнему можете скачать скрытые логи. Если файл лога слишком большой, скачивание может завершиться ошибкой. В этом случае вы можете [обратиться в службу поддержки](mailto:support@getdbt.com).

### Вкладка Model timing <Lifecycle status="self_service,managed,managed_plus" /> {#model-timing-tab}

Вкладка **Model timing** показывает состав моделей, порядок их выполнения и время, затрачиваемое на каждую модель при запуске задания. Это помогает выявить узкие места в запусках, чтобы изучить их и при необходимости внести изменения для повышения производительности. Вкладка доступна на [странице сведений о запуске задания](#job-run-details).

Вкладка включает следующие разделы:

- [Карточки метрик](#metric-tiles)
- [Временная шкала выполнения](#execution-timeline)
- [Параллельное выполнение во времени](#concurrency-over-time)
- [Сведения о ресурсах](#resource-details)

#### Карточки метрик {#metric-tiles}

В верхней части вкладки отображаются шесть карточек метрик:

- **Est. critical path**: Оценочная длительность самой длинной цепочки зависимых моделей и её доля в общем времени запуска в процентах.
- **Peak concurrency**: Максимальное количество одновременно выполнявшихся моделей и момент запуска, когда оно было достигнуто.
- **Avg active models**: Среднее количество активных моделей за время запуска.
- **Longest model**: Длительность выполнения и имя самой медленной модели в запуске.
- **Wall clock**: Общее время, прошедшее от начала до завершения запуска.
- **Latest start**: Имя и время начала выполнения модели, которая начала выполняться последней в запуске.

<Lightbox src="/img/docs/dbt-platform/deployment/model-timing-metric-tiles.png" width="100%" title="Карточки метрик с ключевой статистикой запуска: оценочным критическим путём, пиковым параллелизмом, самой медленной моделью и другими показателями." />

#### Временная шкала выполнения {#execution-timeline}

Временная шкала в виде диаграммы Ганта для всех ресурсов запуска. Наведите указатель на полосы, чтобы увидеть подробности. Представление можно настроить с помощью следующих элементов:

- **Group by**: Определяет, как ресурсы группируются на временной шкале:
  - **Resource type**: Группирует по типу узла: Model, Test, Snapshot или Exposure.
  - **Folder**: Группирует по пути к папке ресурса в вашем проекте.
  - **Execution phase**: Группирует ресурсы по фазам от 0 до 4 в зависимости от времени начала выполнения &mdash; фаза 0 началась раньше всех, а фаза 4 — позже всех.
  - **Thread**: Группирует по потоку выполнения dbt, в котором выполнялся каждый ресурс. dbt использует несколько потоков для параллельного выполнения моделей; это представление показывает, какой поток обрабатывал какие ресурсы.
  - **No grouping**: Показывает все ресурсы без группировки.
- **Highlight**: Изменяет окраску полос, помогая сосредоточиться на нужных данных:
  - **Est. critical path**: Выделяет ресурсы на оценочном критическом пути, отображая все остальные серым цветом.
  - **All equal**: Показывает все полосы в цвете соответствующего типа ресурса без дополнительного выделения. Легенда показывает цвет каждого типа: Model, Test, Snapshot и Exposure.
  - **By duration**: Отображает ресурсы с меньшим временем выполнения серым цветом, а с большим — цветными.
- **Search resources**: Фильтрует временную шкалу, оставляя ресурсы, соответствующие поисковому запросу.

#### Сведения о ресурсах {#resource-details}

Таблица всех ресурсов запуска с поиском и постраничной навигацией. Она содержит следующие столбцы:

- **Model**: Имя ресурса.
- **Start**: Время начала выполнения ресурса.
- **End**: Время завершения выполнения ресурса.
- **Duration**: Продолжительность выполнения ресурса.
- **Execution phase**: Число от 0 до 4, указывающее, когда началось выполнение ресурса относительно остальных ресурсов запуска &mdash; фаза 0 началась раньше всех, а фаза 4 — позже всех.
- **Est. critical path**: Указывает, находится ли ресурс на оценочном критическом пути.
- **Type**: Тип ресурса (Model, Test, Snapshot или Exposure), отображаемый в виде значка с цветовой маркировкой.
- **Folder**: Путь к папке ресурса.

### Вкладка Compare <Lifecycle status="managed,managed_plus" /> {#compare-tab}

Вкладка **Compare** отображается для [запусков заданий CI](/docs/deploy/ci-jobs), для которых включена настройка **Run compare changes**. На ней представлены подробные сведения об [изменениях, выявленных при сравнении, выполненном dbt](/docs/deploy/advanced-ci#compare-changes), между состоянием вашей производственной среды и pull request. Чтобы вам было проще увидеть различия, <Constant name="dbt" /> выделяет изменения в моделях красным (удаления) и зелёным (вставки).

В разделе **Modified** доступны следующие сведения:

- **Overview** &mdash; Высокоуровневое резюме изменений в моделях, например количество добавленных или удалённых первичных ключей.  
- **Primary keys** &mdash; Подробности об изменениях в записях.  
- **Modified rows** &mdash; Подробности об изменённых строках. Нажмите **Show full preview**, чтобы отобразить все колонки.  
- **Columns** &mdash; Подробности об изменениях в колонках.

Чтобы подробнее изучить зависимости и связи между ресурсами вашего проекта, нажмите **Посмотреть в <Constant name="catalog" />**, чтобы открыть [<Constant name="catalog" />](/docs/explore/explore-projects).
