# Контрольный список настройки платформы dbt

Итак, вы создали новый облачный аккаунт dbt platform и готовы начать знакомство с его быстрыми и интуитивно понятными возможностями. Добро пожаловать! Прежде чем приступить к работе, давайте убедимся, что ваш аккаунт настроен корректно — это позволит без проблем подключать новых пользователей и использовать все интеграции, которые предлагает dbt.

Для большинства организаций на этом этапе потребуется взаимодействие с IT‑специалистами и/или командой безопасности. В зависимости от используемых возможностей, вам может понадобиться помощь следующих административных ролей:
- Хранилище данных (Snowflake, BigQuery, Databricks и т.д.)
- Управление доступом (Okta, Entra ID, Google, SAML 2.0)
- Git (GitHub, GitLab, Azure DevOps и т.д.)

Этот чек-лист поможет убедиться, что всё настроено правильно, чтобы вы могли быстро начать работу и избежать узких мест.

## Хранилище данных {#data-warehouse}

Платформа dbt поддерживает [глобальные подключения](/docs/platform/connect-data-platform/about-connections#connection-management) к вашим хранилищам данных. Это означает, что одно настроенное подключение можно использовать в нескольких проектах и средах. Платформа dbt поддерживает подключения к различным хранилищам данных, включая BigQuery, Databricks, Redshift и Snowflake, но не ограничиваясь ими. Один из первых шагов при настройке аккаунта — убедиться, что у вас есть работающее подключение:

- [ ] Используйте [документацию по настройке подключений](/docs/platform/connect-data-platform/about-connections), чтобы настроить подключение к выбранному хранилищу данных. 
- [ ] Убедитесь, что разработчикам dbt назначены необходимые роли и предоставлен доступ к вашим хранилищам данных.
- [ ] Убедитесь, что в хранилище есть реальные данные, к которым можно обращаться. Это могут быть данные из производственной среды или среды разработки. При желании вы можете использовать наш учебный проект электронной коммерции [The Jaffle Shop](https://github.com/dbt-labs/jaffle-shop). The Jaffle Shop включает тестовые данные и готовые к запуску модели!
- [ ] Независимо от того, создаёте ли вы новый проект или импортируете существующий проект <Constant name="core" />, убедитесь, что у него [правильно настроена структура](/docs/build/projects).
    - [ ] Если вы переходите с <Constant name="core" />, вам необходимо учесть несколько важных моментов, поэтому ознакомьтесь с нашим [руководством по миграции](/guides/dbt-migration-2?step=1).
- [ ] Вашим пользователям потребуется [настроить свои учётные данные](/docs/platform/studio-ide/develop-in-studio#get-started-with-the-studio-ide) для подключения к среде разработки в dbt Studio IDE.
    - [ ] Убедитесь, что всем пользователям, которым нужен доступ для работы в IDE, в вашем аккаунте назначена [лицензия разработчика](/docs/platform/manage-access/seats-and-users). 
- [ ] Модели dbt в основном пишутся в виде [инструкций SELECT](/docs/build/sql-models), поэтому один из первых шагов для проверки успешности настройки — попросить разработчика выполнить простую инструкцию SELECT в IDE и проверить результаты. 
    - [ ] Вы также можете проверить подключение, выполнив простые SQL-запросы с помощью [dbt Insights](/docs/explore/access-dbt-insights).
- [ ] Создайте одну модель и убедитесь, что можете успешно [запустить её](/reference/dbt-commands). 
- [ ] Создайте служебную учётную запись с необходимыми правами доступа для ваших [заданий в производственной среде](/docs/deploy/jobs).

## Настройка Git {#git-configuration}

Git является основой большинства dbt‑окружений. Именно в Git‑репозиториях хранятся файлы dbt‑проекта, и именно там разработчики совместно работают над кодом и управляют версиями.

- [ ] Настройте [Git-репозиторий](/docs/platform/git/configure-git) для вашей учетной записи. dbt поддерживает интеграции с:
    - [GitHub](/docs/platform/git/connect-github)
    - [GitLab](/docs/platform/git/connect-gitlab)
    - [Azure DevOps](/docs/platform/git/connect-azure-devops)
    - Другими провайдерами через [Git clone](/docs/platform/git/import-a-project-by-git-url)
    - Если вы пока не готовы интегрироваться с существующим Git-решением, dbt может предоставить вам [управляемый Git-репозиторий](/docs/platform/git/managed-repository). 
- [ ] Убедитесь, что разработчики могут [создать новую ветку и переключиться на нее](/docs/platform/git/version-control-basics#git-overview) в вашем репозитории.
- [ ] Убедитесь, что разработчики могут [фиксировать изменения](/docs/platform/studio-ide/ide-user-interface#basic-layout) в IDE.

## Окружения и job-ы {#environments-and-jobs}

[Environments](/docs/environments-in-dbt) позволяют разделять данные разработки и продакшена. dbt поддерживает два типа окружений: Development и Deployment. Существует три типа Deployment‑окружений:
- Production — одно на проект  
- Staging — одно на проект  
- General — несколько на проект  

Кроме того, в каждом проекте может быть только одно `Development`‑окружение, но у каждого разработчика будет собственный изолированный доступ к IDE, независимый от работы других разработчиков.

[Jobs](/docs/deploy/jobs) определяют, какие команды выполняются в окружениях. Они могут запускаться вручную, по расписанию, другими job‑ами, через API или при создании либо слиянии pull request.

После подключения хранилища данных и завершения интеграции с Git можно переходить к настройке окружений и job‑ов:

- [ ] Начните с создания новой [среды разработки](/docs/dbt-platform-environments#create-a-development-environment) для вашего проекта. 
- [ ] Создайте [среду развертывания Production](/docs/deploy/deploy-environments).
    - [ ] (Необязательно) Создайте дополнительную среду Staging или General.
- [ ] [Создайте задание развертывания и настройте его расписание](/docs/deploy/deploy-jobs#create-and-schedule-jobs). 
    - [ ] Проверьте работу задания, сначала запустив его вручную.
- [ ] При необходимости настройте разные базы данных для ваших сред.

## Пользовательский доступ {#user-access}

dbt platform предоставляет широкий набор инструментов управления доступом, которые позволяют предоставлять и отзывать доступ пользователей, настраивать RBAC, а также назначать лицензии и разрешения.

- [ ] Вручную [пригласите пользователей](/docs/platform/manage-access/invite-users) на платформу dbt, где они смогут проходить аутентификацию с помощью [MFA (SMS или приложения-аутентификатора)](/docs/platform/manage-access/mfa).
- [ ] Настройте [единый вход (SSO) или OAuth](/docs/platform/manage-access/sso-overview) для расширенного управления доступом. Только для аккаунтов <Lifecycle status="managed,managed_plus" />. 
    - [ ] Создайте [сопоставления SSO](/docs/platform/manage-access/about-user-access#sso-mappings-) для групп
- Настройте [System for Cross-Domain Identity Management (SCIM)](/docs/platform/manage-access/scim), если ваш поставщик удостоверений (IdP) поддерживает этот протокол. 
- [ ] Убедитесь, что приглашённые пользователи могут подключаться к хранилищу данных из своего личного профиля. 
- [ ] [Создайте группы](/docs/platform/manage-access/about-user-access#create-new-groups-) и назначьте им наборы разрешений с детальной настройкой.
- [ ] Создайте [правила RBAC](https://docs.getdbt.com/docs/platform/manage-access/about-user-access#role-based-access-control-), чтобы при входе пользователей в систему назначать им группы и наборы разрешений. Только для аккаунтов <Lifecycle status="managed,managed_plus" />. 
- [ ] Сделайте SSO обязательным для всех пользователей без прав администратора и обеспечьте обязательное использование MFA при каждом входе по паролю.
