# Подписание коммитов Git

Чтобы предотвратить подмену личности и повысить безопасность, вы можете подписывать свои <Constant name="git" />-коммиты перед отправкой их в репозиторий. С помощью подписи <Constant name="git" />-провайдер может криптографически проверить коммит и пометить его как «verified», обеспечивая большую уверенность в его происхождении.

Вы можете настроить <Constant name="dbt" /> для подписания коммитов <Constant name="git" /> при разработке в <Constant name="studio_ide" />. Для этого включите эту функцию в <Constant name="dbt" />, выполните шаги по созданию пары ключей и загрузите открытый ключ в ваш сервис <Constant name="git" />, чтобы использовать его для проверки подписей.


## Предварительные требования {#prerequisites}

- Ваш провайдер <Constant name="git" /> — GitHub или GitLab. В настоящее время Azure DevOps не поддерживается.
- У вас есть учетная запись <Constant name="dbt" /> на [тарифном плане Enterprise или Enterprise+](https://www.getdbt.com/pricing/).

## Генерация пары ключей GPG в dbt {#generate-gpg-keypair-in-dbt}

Чтобы создать пару ключей GPG в <Constant name="dbt" />, выполните следующие действия:
1. Перейдите на страницу **Personal profile** (Личный профиль) в <Constant name="dbt" />.
2. Откройте раздел **Signed Commits** (Подписанные коммиты).
3. Включите переключатель **Sign commits originating from this user** (Подписывать коммиты этого пользователя).
4. Будет создана пара ключей GPG. Закрытый ключ будет использоваться для подписи всех последующих коммитов <Constant name="git" />. Открытый ключ будет показан на странице, чтобы вы могли загрузить его своему провайдеру <Constant name="git" />.

## Загрузка публичного ключа в Git-провайдер {#upload-public-key-to-git-provider}

Чтобы загрузить публичный ключ в ваш <Constant name="git" />-провайдер, следуйте подробной документации поддерживаемого <Constant name="git" />-провайдера:

- [Инструкции GitHub](https://docs.github.com/en/authentication/managing-commit-signature-verification/adding-a-gpg-key-to-your-github-account) 
- [Инструкции GitLab](https://docs.gitlab.com/ee/user/project/repository/signed_commits/gpg.html) 

После загрузки публичного ключа в <Constant name="git" />-провайдер ваши <Constant name="git" />-коммиты будут помечаться как «Verified» после отправки изменений в репозиторий.

## Важные моменты {#considerations}

- Пара ключей GPG привязана к пользователю, а не к конкретному аккаунту. Между пользователем и парой ключей существует связь «один к одному». Один и тот же ключ будет использоваться для подписи коммитов во всех аккаунтах, в которых состоит пользователь.
- Пара ключей GPG, созданная в <Constant name="dbt" />, связана с адресом электронной почты, указанным в вашем аккаунте на момент создания пары ключей. Этот адрес определяет автора подписанных коммитов.
- Чтобы ваши коммиты <Constant name="git" /> помечались как «verified», адрес электронной почты в <Constant name="dbt" /> должен быть подтверждён у вашего провайдера <Constant name="git" />. Провайдер <Constant name="git" /> (например, GitHub или GitLab) проверяет, совпадает ли адрес электронной почты в подписанном коммите с подтверждённым адресом в вашем аккаунте у провайдера <Constant name="git" />. Если адреса не совпадают, коммит не будет помечен как «verified».
- Следите за тем, чтобы адрес электронной почты в <Constant name="dbt" /> совпадал с подтверждённым адресом у вашего провайдера <Constant name="git" />, чтобы избежать проблем с проверкой подписи. Если вы измените адрес электронной почты в <Constant name="dbt" />:
  - Создайте новую пару ключей GPG с обновлённым адресом электронной почты, следуя [описанным ранее шагам](/docs/platform/studio-ide/git-commit-signing#generate-gpg-keypair-in-dbt).
  - Добавьте и подтвердите новый адрес электронной почты у вашего провайдера <Constant name="git" />.

## Часто задаваемые вопросы {#faqs}

<!-- vale on -->

<DetailsToggle alt_header="Что произойдёт, если я удалю свою пару ключей GPG в dbt?">

Если вы удалите свою пару ключей GPG в <Constant name="dbt" />, ваши коммиты Git больше не будут подписываться. Вы можете сгенерировать новую пару ключей GPG, выполнив [описанные ранее шаги](/docs/platform/studio-ide/git-commit-signing#generate-gpg-keypair-in-dbt).
</DetailsToggle>

<DetailsToggle alt_header="Какие Git-провайдеры поддерживают GPG-ключи?">

GitHub и GitLab поддерживают подписание коммитов, в то время как Azure DevOps — нет. Подписание коммитов — это [функция git](https://git-scm.com/book/ms/v2/Git-Tools-Signing-Your-Work), независимая от конкретного провайдера. Однако не все провайдеры поддерживают загрузку публичных ключей или отображение значков проверки для коммитов.

</DetailsToggle>

<DetailsToggle alt_header="Что делать, если мой Git-провайдер не поддерживает GPG-ключи?">

Если ваш Git-провайдер явно не поддерживает загрузку публичных GPG-ключей, 
коммиты всё равно будут подписываться с использованием приватного ключа, 
но информация о проверке не будет отображаться у провайдера.

</DetailsToggle>

<DetailsToggle alt_header="Что делать, если Git-провайдер требует, чтобы все коммиты были подписаны?">

Если ваш Git-провайдер настроен на обязательную проверку коммитов, 
неподписанные коммиты будут отклоняться. Чтобы избежать этого, убедитесь, что вы выполнили все предыдущие шаги по генерации пары ключей 
и загрузили публичный ключ в провайдера.

</DetailsToggle>
