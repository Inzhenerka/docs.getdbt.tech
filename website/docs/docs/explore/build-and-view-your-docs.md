<Constant name="dbt" /> позволяет генерировать документацию для вашего проекта и платформы данных. Документация автоматически обновляется с учётом новой информации после полностью успешного выполнения задания, что обеспечивает её точность и актуальность.

По умолчанию для работы с документацией в <Constant name="dbt" /> используется [<Constant name="catalog" />](/docs/explore/explore-projects), доступный на [тарифных планах Starter, Enterprise или Enterprise+](https://www.getdbt.com/pricing/). Используйте [<Constant name="catalog" />](/docs/explore/explore-projects), чтобы просматривать ресурсы проекта (например, модели, тесты и метрики) и связи между ними и лучше понимать текущее состояние проекта в производственной среде.

Обратитесь к [документации](/docs/build/documentation) для получения более подробной информации о конфигурации.

<VersionBlock lastVersion="1.99">

В результате этого перехода [dbt Docs](#dbt-docs) становится устаревшим средством документирования в <Constant name="dbt" />. dbt Docs по-прежнему доступен и предоставляет базовые возможности документирования, но уступает <Constant name="catalog" /> по скорости работы, объёму метаданных и наглядности. dbt Docs доступен пользователям тарифных планов <Constant name="dbt" /> для разработчиков и пользователям <Constant name="core_v1" />.

</VersionBlock>

<VersionBlock firstVersion="2.0">

Чтобы создать статический сайт документации для размещения на собственной инфраструктуре, используйте [dbt Docs v2](/docs/build/view-documentation#dbt-docs-v2) локально. dbt Docs v2 недоступен в <Constant name="dbt_platform" />.

</VersionBlock>

## Настройка задания для документации {#set-up-a-documentation-job}

<VersionBlock lastVersion="1.99">

<Constant name="catalog" /> использует [метаданные](/docs/explore/explore-projects#generate-metadata), создаваемые после каждого запуска задания в среде production или staging, благодаря чему в нём всегда доступны актуальные результаты проекта. Чтобы просматривать более подробные метаданные, настройте создание документации для задания в <Constant name="dbt" /> при изменении настроек существующего задания или создании нового.

Настройте задание так, чтобы при его выполнении [создавались метаданные](/docs/explore/explore-projects#generate-metadata). Этот шаг необходим, если вы хотите просматривать сведения о столбцах и статистику для моделей, источников и снимков в <Constant name="catalog" />.

Чтобы настроить задание на генерацию документации:

1. В левом верхнем углу нажмите **Deploy** и выберите **Jobs**.
2. Создайте новое задание или выберите существующее и нажмите **Settings**.
3. В разделе **Execution Settings** выберите **Generate docs on run** и нажмите **Save**.
   <Lightbox src="/img/docs/dbt-platform/using-dbt-platform/documentation-job-execution-settings.png" width="100%" title="Настройка задания для генерации документации"/>

*Примечание: для пользователей dbt Docs необходимо настроить задание на генерацию документации при его выполнении, а затем вручную связать это задание с вашим проектом. Перейдите к [настройке документации проекта](#configure-project-documentation), чтобы ваш проект генерировал документацию при выполнении этого задания.*

Вы также можете добавить команду [`dbt docs generate`](/reference/commands/cmd-docs) в список команд в шагах выполнения задания. Однако вы можете ожидать разные результаты при добавлении команды в шаги выполнения по сравнению с настройкой задания, выбрав флажок **Generate docs on run**.

Рассмотрите следующие варианты и результаты:

| Варианты | Результаты |
|--------| ------- |
| **Выбор флажка** | Выберите флажок **Generate docs on run**, чтобы автоматически генерировать обновленную документацию проекта каждый раз при выполнении вашего задания. Если этот конкретный шаг в вашем задании не удастся, задание все равно может быть успешным, если все последующие шаги будут успешными. |
| **Добавить как шаг выполнения** | Добавьте `dbt docs generate` в список команд в шагах выполнения задания в любом порядке, который вы предпочитаете. Если этот конкретный шаг в вашем задании не удастся, задание не удастся, и все последующие шаги будут пропущены. |

:::tip Совет &mdash; Задания только для документации

Чтобы создать и запланировать задания только для документации в конце ваших производственных заданий, добавьте команду `dbt compile` в раздел **Commands**.

:::

## dbt Docs {#dbt-docs}

dbt Docs, доступный на тарифных планах для разработчиков или пользователям <Constant name="core_v1" />, генерирует веб-сайт на основе вашего проекта dbt с помощью команды `dbt docs generate`. Он предоставляет единое место для просмотра ресурсов вашего проекта, таких как модели, тесты и граф происхождения данных (lineage)  &mdash; и помогает вам понять данные в вашем хранилище.

### Настройка документации проекта {#configure-project-documentation}

Вы настраиваете документацию проекта для генерации документации, когда выполняется задание, которое вы настроили в предыдущем разделе. В настройках проекта укажите задание, которое генерирует артефакты документации для этого проекта. После настройки этого параметра последующие выполнения задания автоматически будут включать шаг для генерации документации.

1. В <Constant name="dbt" /> нажмите на название своей учетной записи в левом меню и выберите **Account settings**.
2. Перейдите в раздел **Projects** и выберите проект, для которого нужна документация.
3. Нажмите **Edit**.
4. В разделе **Artifacts** выберите задание, которое должно генерировать документацию при запуске, и нажмите **Save**.
   <Lightbox src="/img/docs/dbt-platform/using-dbt-platform/documentation-project-details.png" width="100%" title="Настройка документации проекта"/>

:::tip Используйте <Constant name="catalog" /> для более широких возможностей работы с документацией
Чтобы сделать работу с документацией более удобной и интерактивной, попробуйте [<Constant name="catalog" />](/docs/explore/explore-projects), доступный на [тарифных планах Starter, Enterprise и Enterprise+](https://www.getdbt.com/pricing/). Он поддерживает слои отображения вашего DAG, поиск по ключевым словам, взаимодействие с <Constant name="studio_ide" />, анализ производительности моделей, рекомендации по проекту и многое другое.
:::

### Генерация документации {#generating-documentation}

Чтобы сгенерировать документацию в <Constant name="studio_ide" />, выполните команду `dbt docs generate` (только для <Constant name="core_v1" />) в **панели команд** в <Constant name="studio_ide" />. Эта команда сгенерирует документацию для вашего проекта dbt в его текущем состоянии в среде разработки в рамках вашего сеанса IDE.

После выполнения `dbt docs generate` в <Constant name="studio_ide" /> нажмите значок над деревом файлов, чтобы открыть последнюю версию документации в новом окне браузера.

### Просмотр документации {#view-documentation}

После настройки задания для генерации документации вашего проекта нажмите **Catalog** в меню навигации, а затем — **dbt Docs**. Откроется документация вашего проекта. Эта ссылка всегда ведёт к последней версии документации вашего проекта в <Constant name="dbt" />.

Эти сгенерированные документы всегда показывают последний полностью успешный запуск, что означает, что если у вас есть какие-либо неудачные задачи, включая тесты, то вы не увидите изменений в документации от этого запуска. Если вы не видите полностью успешного запуска, то вы не увидите никаких изменений в документации.

<Constant name="studio_ide" /> позволяет просматривать [документацию](/docs/build/documentation) вашего проекта dbt, пока код ещё находится в разработке. Такой рабочий процесс позволяет проверить, как будет выглядеть сгенерированная документация проекта, прежде чем изменения попадут в продакшен.

</VersionBlock>

<VersionBlock firstVersion="2.0">

<Constant name="catalog" /> использует [метаданные](/docs/explore/explore-projects#generate-metadata) каждого запуска задания в вашей продакшен-среде или среде предварительного тестирования (staging). Задания, выполняемые на v2, автоматически генерируют эти метаданные при каждом запуске, поэтому отдельное задание для документации, шаг `dbt docs generate` или флажок генерации документации не нужны.

Чтобы поддерживать <Constant name="catalog" /> в актуальном состоянии:

1. В левом верхнем углу нажмите **Deploy** и выберите **Jobs**.
2. Создайте новое задание или выберите существующее задание в продакшен-среде или среде staging и нажмите **Settings**.
3. В разделе **Execution settings** добавьте команды, которые хотите выполнить, например `dbt build`, и нажмите **Save**.
4. После выполнения задания нажмите **Catalog** в меню навигации, чтобы изучить свой проект.

Если вы добавите `dbt docs generate` в качестве шага выполнения, dbt вместо этого выполнит `dbt compile --write-catalog` и отобразит баннер, направляющий вас в <Constant name="catalog" />. Подробнее см. в разделе [Поведение платформы](/reference/commands/cmd-docs?version=2#dbt-platform-behavior).

:::tip Задания только для обновления метаданных
Чтобы обновить метаданные <Constant name="catalog" /> без построения моделей, добавьте `dbt compile --write-catalog` в раздел **Commands**.
:::

## Просмотр документации проекта

[<Constant name="catalog" />](/docs/explore/explore-projects) — это место для просмотра документации вашего проекта в <Constant name="dbt_platform" />. Здесь всегда отображается последнее состояние проекта в продакшене, поэтому вам не нужно ничего развёртывать или размещать на хостинге. В <Constant name="catalog" /> вы можете:

- Искать и фильтровать ресурсы проекта, такие как модели, источники и метрики.
- Изучать [граф зависимостей](/docs/explore/explore-projects#project-lineage), чтобы видеть связи между ресурсами.
- Открывать [сведения о ресурсе](/docs/explore/explore-projects#view-resource-details), чтобы просматривать его описание, столбцы, тесты и результаты последних запусков.

Чтобы открыть его, нажмите **Catalog** в меню навигации. Чтобы изучить модель на графе зависимостей, выберите свой проект на левой боковой панели, нажмите **View lineage**, а затем нажмите на модель, чтобы просмотреть её описание.

<Lightbox src="/img/docs/collaborate/dbt-explorer/example-project-lineage-graph.png" width="100%" title="Пример полного графа зависимостей в Catalog" />

<Constant name="catalog" /> доступен пользователям с правами Developer и пользователям с доступом только для чтения. Чтобы поделиться проектом с заинтересованными сторонами, которые не занимаются разработкой в dbt, предоставьте всем соответствующим пользователям [доступ только для чтения](/docs/platform/manage-access/seats-and-users) к <Constant name="catalog" /> без ограничений.

</VersionBlock>
