**Финальный релиз:** 25 января 2023 года

<Constant name="dbt" /> v1.4 — это релиз с изменениями «под капотом». Мы усердно работали над перестройкой внутренних механизмов `dbt-core` на более надежной основе, чтобы подготовиться к насыщенному году разработки новых возможностей. Ознакомьтесь с [планом релиза v1.5](https://github.com/dbt-labs/dbt/milestone/82) на GitHub, чтобы узнать, что запланировано на апрель.

## Что нужно знать перед обновлением

dbt Labs стремится обеспечивать обратную совместимость для всех версий 1.x. Если после обновления возникнет ошибка, сообщите нам об этом, [создав issue](https://github.com/dbt-labs/dbt/issues/new).

### Для пользователей артефактов dbt (метаданных)

Версия схемы манифеста обновлена до `v8`. Эти изменения касаются тех, кто разбирает или анализирует содержимое файла `manifest.json` либо использует собственный код для обращения к переменным [`model`](/reference/dbt-jinja-functions/model) или [`graph`](/reference/dbt-jinja-functions/graph), например `{{ model.root_path }}`.

Значимые изменения:
- Атрибут `root_path` удален из узлов, не относящихся к seed, чтобы сократить дублирование информации.
- Неиспользуемые атрибуты удалены из узлов seed (включая `depends_on.nodes`) и из `macros` (включая `tags`).
- Значения `unique_id` блоков docs теперь начинаются с `doc` для единообразия с другими типами ресурсов.

### Для разработчиков и сопровождающих плагинов адаптеров

> **Кратко:** Для этой минорной версии значительных доработок не потребуется. Мы ожидаем большего объема работы для `1.5.0`. Мы планируем выпускать бета-версии заранее и часто, а также предоставлять рекомендации по обновлению.

Основные изменения:
- Добавление поддержки Python 3.11
- Переименование или замена устаревших функций обработки исключений
- Добавление поддержки предикатов для инкрементальных моделей (если применимо)
- Использование новых тестов adapter-zone

Более подробную информацию можно найти в [<Constant name="core" />/discussions/6624](https://github.com/dbt-labs/dbt/discussions/6624), где также можно задать вопросы.

## Новая и обновленная документация

- [**События и структурированное логирование**](/reference/events-logging): Система событий dbt была переработана. Информация стала более единообразной по доступности и структуре благодаря типобезопасным схемам событий.
- [**Поддержка Python**](/faqs/Core/install-python-compatibility): Python 3.11 вышел в октябре 2022 года. Он официально поддерживается в dbt-core v1.4, хотя полная поддержка также зависит от плагина адаптера для вашей платформы данных. По словам разработчиков Python, «Python 3.11 на 10–60% быстрее Python 3.10». Мы рекомендуем попробовать [`dbt parse`](/reference/commands/parse) с <Constant name="dbt" /> v1.4 + Python 3.11 и сравнить время выполнения с <Constant name="dbt" /> v1.3 + Python 3.10. Поделитесь результатами!
- [**Метрики**](/docs/build/build-metrics-intro): Параметр `time_grain` стал необязательным, чтобы упростить работу с метриками, не привязанными ко времени.
- **Контекст dbt-Jinja:** Метод контекста [local_md5](/reference/dbt-jinja-functions/local_md5) вычисляет [MD5-хеш](https://en.wikipedia.org/wiki/MD5) для использования _внутри_ dbt. (Не путать с md5 в SQL!)
- [**Exposures**](/docs/build/exposures) теперь могут зависеть от `metrics`.
- [**Пакеты в tar-архивах**](/docs/build/packages#internally-hosted-tarball-url): В некоторых организациях требования безопасности разрешают загружать ресурсы только из внутренних сервисов. Чтобы обеспечить установку пакетов из сред хранения (например, Artifactory или бакетов облачного хранилища), теперь можно указать любой доступный URL, по которому можно скачать сжатый пакет dbt.
- [**Детальная настройка «предупреждений как ошибок»**](/reference/global-configs/warnings): Благодаря полной переработке и унификации классов предупреждений и исключений в `dbt-core` теперь можно задать более детальную конфигурацию `--warn-error-options`, указав, какие именно предупреждения dbt должен (или не должен) считать ошибками.
- [**Отложенное разрешение ссылок (deferral)**](/reference/node-selection/defer#favor-state) поддерживает необязательный параметр `--favor-state`.

### Расширенные настройки инкрементальных моделей

- [**Параметр `incremental_predicates`**](/docs/build/incremental-strategy#about-incremental_predicates) теперь поддерживается наиболее популярными адаптерами, обеспечивая большую гибкость при настройке производительности операторов `merge` и `delete` для больших наборов данных.
- **BigQuery:** Инкрементальная стратегия `insert_overwrite` поддерживает новый (старый) механизм — [`time_ingestion_partitioning`](/reference/resource-configs/bigquery-configs#partitioning-by-an-ingestion-date-or-timestamp) + [`copy_partitions`](/reference/resource-configs/bigquery-configs#copying-partitions), который позволяет значительно сократить затраты и время обработки больших наборов данных.

### Обновления моделей Python {#updates-to-python-models}

- Для моделей Python по умолчанию [настроена материализация](/docs/build/python-models) `table`.
- Модели Python, [выполняемые в Snowpark](/docs/build/python-models), по умолчанию будут использовать «анонимные» хранимые процедуры, что немного ускорит выполнение и сделает историю запросов чище.
