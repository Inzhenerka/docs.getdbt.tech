Архивные примечания к выпускам <Constant name="dbt" /> за 2022 год

## Декабрь 2022 {#december-2022}

### Значение threads по умолчанию изменено на 4 {#threads-default-value-changed-to-4}

Threads помогают распараллеливать выполнение узлов в направленном ациклическом графе dbt [(DAG)](https://docs.getdbt.com/terms/dag).

Ранее значение threads по умолчанию было равно 1, что могло увеличивать время выполнения вашего проекта. Чтобы сократить время выполнения, значение threads по умолчанию в пользовательских профилях теперь установлено равным 4.

При необходимости вы можете указать собственное количество threads, если вам требуется больше или меньше параллелизма.

Подробнее см. в разделе [Understanding threads](/docs/running-a-dbt-project/using-threads).

### Создание нового job больше не запускает выполнение по умолчанию {#creating-a-new-job-no-longer-triggers-a-run-by-default}

Чтобы сократить затраты вычислительного времени, новые задания больше не будут запускаться по умолчанию. При создании нового задания в <Constant name="dbt" /> вы можете настроить его запуск, выбрав **Run on schedule** и указав нужное расписание и время запуска.

Подробнее см. в разделе [Deploy jobs](/docs/deploy/deploy-jobs).

### Приватные пакеты необходимо клонировать с использованием токенов доступа, передаваемых через переменные окружения

Поддерживаемый способ клонирования приватных пакетов GitHub — это [метод git token](/docs/build/packages#git-token-method), при котором соответствующий access token передается в URL репозитория пакета через переменную окружения.

Небольшое число пользователей могли клонировать приватные пакеты, используя нативное GitHub-приложение dbt без явного указания access token. Эта функциональность выводится из эксплуатации, так как она обладает ограниченной гибкостью.

Если вы используете пакет, размещенный в приватном репозитории GitHub, теперь необходимо начать передавать access token в URL.

Пример передачи access token:

<File name='packages.yml'>

```yaml

packages:
- git: "https://{{env_var('DBT_ENV_SECRET_GIT_CREDENTIAL')}}@github.com/dbt-labs/awesome_repo.git"

```

</File>

## Сентябрь 2022 {#september-2022}

### Предупреждение о выводе из эксплуатации API endpoint List Steps {#list-steps-api-endpoint-deprecation-warning}

14 октября 2022 года dbt Labs выведет из эксплуатации API endpoint List Steps. Начиная с этой даты любые GET-запросы к этому endpoint будут завершаться ошибкой. Пожалуйста, как можно скорее подготовьтесь к отказу от использования List Steps.

dbt Labs продолжит поддерживать endpoint [Retrieve Run](/dbt-cloud/api-v2#/operations/Retrieve%20Run), который может служить альтернативой в зависимости от сценария использования.

Вы можете получить шаги выполнения отдельного запуска с помощью GET-запроса по следующему URL, заменив `YOUR_ACCESS_URL` на [соответствующий URL доступа](/docs/platform/about-platform/access-regions-ip-addresses) для вашего региона и тарифного плана:

`https://YOUR_ACCESS_URL/api/v2/accounts/{accountId}/runs/{runId}/?include_related=["run_steps"]`

### Запрос данных за последние три месяца через metadata API {#query-the-previous-three-months-of-data-using-the-metadata-api}

Чтобы сделать metadata API более масштабируемым и снизить задержки, были внедрены ограничения на хранение данных. Теперь metadata API позволяет запрашивать данные только за последние три месяца. Например, если сегодня 1 марта, вы сможете получить данные, начиная с 1 января.

Дополнительную информацию см. в разделе [Metadata API](/docs/dbt-apis/discovery-api)

### Обновление просроченных access token в IDE при использовании GitLab {#refresh-expired-access-tokens-in-the-ide-when-using-gitlab}

22 мая GitLab изменил порядок обработки [токенов доступа OAuth без срока действия](https://docs.gitlab.com/ee/update/deprecations.html#oauth-tokens-without-expiration). ## Апрель 2022 {#april-2022}

### Журнал аудита {#audit-log}

Для просмотра действий, выполненных пользователями вашей организации, dbt предоставляет журналы аудита пользовательских и системных событий. Журнал аудита <Constant name="dbt" /> содержит события, произошедшие в вашей организации за последние 90 дней. 

Журнал аудита содержит такие сведения, как кто выполнил действие, что это было за действие и когда оно было выполнено. Дополнительные сведения см. в документации [по журналу аудита для <Constant name="dbt" /> Enterprise](/docs/platform/manage-access/audit-log).

### Учетные данные больше не удаляются при редактировании окружения {#credentials-no-longer-accidentally-wiped-when-editing-an-environment}

Мы исправили ошибку, из-за которой обновление незашифрованных полей (например, threads, имя схемы) в настройках окружения приводило к удалению секретных полей (например, пароля, keypair, данных учетных записей). Теперь пользователи могут безопасно обновлять настройки окружения без риска случайной потери учетных данных.

### Подтверждение email {#email-verification}

Для повышения безопасности создания пользователей пользователи <Constant name="dbt" />, созданные с помощью SAML Just-in-Time (JIT), теперь должны подтверждать свою личность по электронной почте, чтобы активировать учётную запись. Подтверждение личности по электронной почте позволяет убедиться, что у пользователя по-прежнему есть доступ к тому же адресу электронной почты, который он использует для входа через SAML.

### Улучшения производительности планировщика {#scheduler-performance-improvements}

Мы развернули новый распределенный планировщик, который значительно ускоряет этап подготовки, особенно в начале часа. Подробнее о проделанной работе и улучшениях — в нашем [блоге продуктовых новостей](https://www.getdbt.com/blog/a-good-problem-to-have/).

### Нестабильное интернет-соединение больше не вызывает сообщение о завершении сессии {#spotty-internet-issues-no-longer-cause-a-session-time-out-message}

Мы исправили проблему, из-за которой при нестабильном интернет-соединении могло неожиданно появляться сообщение «Время ожидания сеанса <Constant name="studio_ide" /> истекло». Чаще всего с этой проблемой сталкивались пользователи VPN.

### Разделение queue time на waiting time и prep time {#dividing-queue-time-into-waiting-and-prep-time}

<Constant name="dbt" /> теперь показывает «время ожидания» и «время подготовки» для запуска, которые раньше отображались вместе как «время в очереди». Время ожидания — это время, в течение которого <Constant name="dbt" /> ожидает возможности запустить ваше задание, если нет свободного слота для запуска или предыдущий запуск того же задания ещё выполняется. Время подготовки — это время, необходимое <Constant name="dbt" /> для подготовки вашего задания к выполнению в облачном хранилище данных.
