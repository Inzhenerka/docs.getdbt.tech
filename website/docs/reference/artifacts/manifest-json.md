**Создаётся командами**: Любая [команда dbt](/reference/commands/invocation), которая выполняет разбор проекта. Сюда входят все команды, _кроме_ [`deps`](/reference/commands/deps), [`clean`](/reference/commands/clean), [`debug`](/reference/commands/debug) и [`init`](/reference/commands/init).

После выполнения команды dbt файл `manifest.json` можно найти в каталоге `target/` проекта:

- При локальной разработке: откройте каталог `target/` в папке проекта
- В <Constant name="studio_ide" />: откройте каталог `target/` в дереве файлов
- В заданиях <Constant name="dbt_platform" />: скачайте `manifest.json` с вкладки [артефактов](/reference/artifacts/dbt-artifacts) для конкретного запуска задания

Этот файл содержит полное представление ресурсов вашего проекта dbt (моделей, тестов, макросов и многого другого), включая все конфигурации узлов и свойства ресурсов. Даже если вы запускаете лишь некоторые модели или тесты, в манифесте будут представлены все ресурсы (если они не отключены) с большинством их свойств. Некоторые свойства, такие как `compiled_sql`, включаются только для выполненных узлов.

В настоящее время dbt использует этот файл для наполнения [сайта документации](/docs/explore/build-and-view-your-docs) и для [сравнения состояний](/reference/node-selection/syntax#how-does-selection-work). Участники сообщества также используют его для анализа состояния проекта, например для проверки наличия описаний или тестов.

### Ключи верхнего уровня {#top-level-keys}

- [`metadata`](/reference/artifacts/dbt-artifacts#common-metadata)
- `nodes`: Словарь всех анализов, моделей, seed-файлов, снимков и тестов.
- `sources`: Словарь источников
- `metrics`: Словарь метрик
- `exposures`: Словарь экспозиций
- `groups`: Словарь групп (**Примечание:** добавлено в v1.5)
- `macros`: Словарь макросов
- `docs`: Словарь блоков `docs`
- `parent_map`: Словарь, содержащий непосредственных родителей каждого ресурса
- `child_map`: Словарь, содержащий непосредственных потомков каждого ресурса
- `group_map`: Словарь, сопоставляющий имена групп с узлами их ресурсов
- `selectors`: Развёрнутое представление [YAML-селекторов `selectors`](/reference/node-selection/yaml-selectors) в виде словаря
- `disabled`: Массив ресурсов с `enabled: false`

### Детали ресурсов {#resource-details}

Все ресурсы, вложенные в `nodes`, `sources`, `metrics`, `exposures`, `macros` и `docs`, имеют следующие базовые свойства:

- `name`: Имя ресурса
- `unique_id`: `<resource_type>.<package>.<resource_name>`, совпадает с ключом словаря
- `package_name`: Имя пакета, в котором определён этот ресурс
- `root_path`: Абсолютный путь к пакету этого ресурса. (**Примечание:** Это поле было удалено для большинства типов узлов в <Constant name="dbt" /> v1.4 / manifest v8, чтобы сократить дублирование информации между узлами, но оно по-прежнему присутствует для seeds.)
- `path`: Относительный путь к файлу, в котором определён этот ресурс, в пределах соответствующего «пути к ресурсам» (`model-paths`, `seed-paths` и других).
- `original_file_path`: Относительный путь к файлу, в котором определён этот ресурс, включая путь к ресурсам.

Каждый из них имеет несколько дополнительных свойств, связанных с его типом ресурса.

### JSON-схема dbt
Сведения об описании и использовании артефактов, созданных dbt, можно найти в [JSON-схеме dbt](https://schemas.getdbt.com/).

**Примечание**: Номер версии `manifest.json` связан с (но не _равен_) вашей версии dbt, поэтому вы _должны_ использовать правильную версию `manifest.json` для вашей версии dbt. Чтобы найти правильную версию `manifest.json`, выберите версию dbt в верхней навигации (например, `v1.5`).

См. таблицу в начале [этой страницы](/reference/artifacts/manifest-json), чтобы понять, как версия манифеста соотносится с версией dbt.
