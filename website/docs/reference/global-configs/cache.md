### Заполнение кэша {#cache-population}

В начале выполнения dbt кэширует метаданные обо всех объектах во всех схемах, где могут быть материализованы ресурсы (такие как модели). По умолчанию dbt заполняет реляционный кэш информацией обо всех схемах, связанных с проектом.

При необходимости изменить это поведение можно двумя способами:
- `POPULATE_CACHE` (по умолчанию: `True`): Определяет, нужно ли вообще заполнять кеш. Чтобы полностью пропустить заполнение кеша, используйте флаг `--no-populate-cache` или <VersionBlock lastVersion="1.10">`DBT_POPULATE_CACHE: False`</VersionBlock><VersionBlock firstVersion="1.11">`DBT_ENGINE_POPULATE_CACHE: False`</VersionBlock>. Обратите внимание: это не _отключает_ кеш; если нужные данные не найдены в кеше, будут выполнены запросы, после чего кеш будет обновлён.
- `CACHE_SELECTED_ONLY` (по умолчанию: `False`): Определяет, нужно ли ограничить заполнение кеша только ресурсами, выбранными для текущего запуска. Это может значительно ускорить выполнение при запуске небольшой части большого проекта, сохраняя при этом преимущества предварительного кеширования.

Например, чтобы быстро скомпилировать модель, которая не требует метаданных базы данных или интроспективных запросов:
```text
dbt compile --no-populate-cache --select my_model_name
```

Или, чтобы улучшить скорость и производительность при разработке моделей Salesforce, которые материализуются в своей собственной выделенной схеме, вы можете выбрать эти модели и передать флаг `cache-selected-only`:

```text
dbt run --cache-selected-only --select salesforce
```
