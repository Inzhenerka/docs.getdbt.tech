Программные вызовы позволяют вызывать команды dbt из скриптов и приложений на Python, а не запускать их в командной оболочке. Это полезно, когда нужно встроить запуски dbt в более крупное приложение или рабочий процесс, используя при этом тот же набор команд, что и в dbt CLI.

Типичные сценарии использования:

- Запуск dbt как части приложения или сервиса на Python
- Интеграция запусков dbt в процессы оркестрации
- Создание внутренних инструментов, которым нужно выполнять команды dbt и анализировать результаты

Если вы ещё не установили официальный пакет Python для <Constant name="core" />, перейдите на страницу [пакета <Constant name="core" /> на PyPI](https://pypi.org/project/dbt-core/) для его установки.

<VersionBlock lastVersion="1.99">

```python
from dbt.cli.main import dbtRunner, dbtRunnerResult

# инициализация
dbt = dbtRunner()

# создание аргументов CLI в виде списка строк
cli_args = ["run", "--select", "tag:my_tag"]

# выполнение команды
res: dbtRunnerResult = dbt.invoke(cli_args)

# проверка результатов
for r in res.result:
    print(f"{r.node.name}: {r.status}")
```

Подробности реализации см. в исходных определениях `dbtRunner` и `dbtRunnerResult` в [репозитории <Constant name="core" />](https://github.com/dbt-labs/dbt/blob/1.latest/core/dbt/cli/main.py).

</VersionBlock>

<VersionBlock firstVersion="2.0">

```python
from dbt.cli.main import dbtRunner, dbtRunnerResult

# initialize
dbt = dbtRunner()

# create CLI args as a list of strings
cli_args = ["run", "--select", "tag:my_tag"]

# run the command
res: dbtRunnerResult = dbt.invoke(cli_args)

# inspect the results
for r in res.result:
    print(f"{r.unique_id}: {r.status}")
```

Подробности реализации см. в [крейте `dbt-python`](https://github.com/dbt-labs/dbt/tree/main/crates/dbt-python) в репозитории <Constant name="core" />.

</VersionBlock>

## Поддерживаемые аргументы

`dbtRunner.invoke` принимает те же аргументы, что и dbt CLI. Первый позиционный аргумент — это команда (например, `run`, `build`, `test`), за которой следуют флаги и параметры, которые вы обычно передаёте в командной строке.

Например, `dbt.invoke(["run", "--select", "tag:my_tag"])` эквивалентен выполнению `dbt run --select tag:my_tag`. Отдельного списка аргументов для dbtRunner нет; официальным источником информации о доступных параметрах служат справка CLI (`dbt --help`, `dbt run --help` и т. д.) и [справочник команд dbt](/reference/dbt-commands).

```python
from dbt.cli.main import dbtRunner
dbt = dbtRunner()
# equivalent ways to pass arguments
dbt.invoke(["run", "--select", "tag:my_tag"])
dbt.invoke(["run"], select="tag:my_tag")
```

## Параллельное выполнение не поддерживается {#parallel-execution-not-supported}

dbt не поддерживает [безопасное параллельное выполнение](/reference/dbt-commands#parallel-execution) нескольких вызовов в одном процессе. Одновременное выполнение нескольких команд dbt в одном процессе небезопасно и официально не рекомендуется; для этого требуется процесс-обёртка, управляющий подпроцессами. Причины следующие:

- Одновременно выполняемые команды могут непредвиденным образом взаимодействовать с платформой данных. Например, одновременное выполнение `dbt run` и `dbt build` для одних и тех же моделей может привести к непредсказуемым результатам.
- Каждая команда `dbt` взаимодействует с глобальными переменными Python. Для безопасной работы команды необходимо выполнять в отдельных процессах, например создавая подпроцессы или используя Celery для оркестрации.

Для [безопасного параллельного выполнения](/reference/dbt-commands#available-commands) можно использовать [<Constant name="platform_cli" />](/docs/platform/dbt-cli-installation) или [<Constant name="studio_ide" />](/docs/platform/studio-ide/develop-in-studio): оба инструмента берут на себя дополнительную работу по управлению одновременным выполнением в нескольких процессах.

<VersionBlock firstVersion="2.0">

В v2 вызовы выполняются последовательно благодаря блокировкам на уровне потоков, поэтому несколько вызовов не могут выполняться одновременно в одном процессе. (В v1 параллельное выполнение не поддерживалось, но блокировок не было, поэтому вызовы всё же могли выполняться в многопоточном режиме.) Как и в v1, вы по-прежнему можете распараллеливать выполнение, используя несколько процессов и выполняя каждый вызов в отдельном процессе.

</VersionBlock>

## `dbtRunnerResult` {#dbtrunnerresult}

Каждая команда возвращает объект `dbtRunnerResult` со следующими атрибутами:

- `success` (bool): Указывает, успешно ли выполнена команда.
- `result`: Когда команда завершается (успешно или с обработанными ошибками), содержит результат или результаты команды. Тип возвращаемого значения зависит от команды.
- `exception`: Когда при вызове dbt возникает необработанная ошибка и выполнение не завершается, содержит возникшее исключение.
- `catalog` (только v2): Каталог, который команда создаёт при запросе генерации каталога. 

<VersionBlock firstVersion="2.0">

Движок v2 реализован на Rust, поэтому `exception` больше не содержит исходный объект исключения Python, возникшего в dbt. Вместо этого перехваченное сообщение об ошибке передаётся в исключении соответствующего типа:

- Если вызов завершается с ошибкой на границе интерфейса внешних функций (FFI), прежде чем движок начнёт его обрабатывать, `exception` содержит исключение без дополнительной обёртки, например `ValueError` или `RuntimeError`.
- Если вызов завершается с ошибкой внутри движка, `exception` содержит `DbtRunnerError`.

В v2 в `dbtRunnerResult` также добавляется атрибут верхнего уровня `catalog`, если запрошена генерация каталога.

В v1 файл `catalog.json` создавался только при запуске `dbt docs generate`. В v2 каталог можно сгенерировать при выполнении любой команды, передав [флаг `--write-catalog`](/reference/commands/cmd-docs?version=2.0#--write-catalog-flag). Например, `dbt run --write-catalog` заполняет и `dbtRunnerResult.result`, и `dbtRunnerResult.catalog`.

</VersionBlock>

Между [кодами завершения CLI](/reference/exit-codes) и объектом `dbtRunnerResult`, возвращаемым при программном вызове, существует взаимно однозначное соответствие:

| Сценарий                                                                                    | Код завершения CLI | `success` | `result`         | `exception` |
|---------------------------------------------------------------------------------------------|--------------:|-----------|-------------------|-------------|
| Вызов завершился без ошибок                                                                 | 0             | `True`      | зависит от команды | `None`        |
| Вызов завершился как минимум с одной обработанной ошибкой (например, сбоем теста или ошибкой построения модели) | 1             | `False`     | зависит от команды | `None`        |
| Необработанная ошибка. Вызов не завершился и не возвращает результатов.                       | 2             | `False`     | `None`              | Исключение   |

## Обязательства и оговорки

Мы берём на себя долгосрочное обязательство предоставлять точку входа Python, функционально эквивалентную CLI <Constant name="core" />. Мы оставляем за собой право менять внутреннюю реализацию, используемую для достижения этой цели. Мы ожидаем, что текущая реализация позволит решать реальные задачи в краткосрочной и среднесрочной перспективе, пока мы работаем над набором стабильных, долгосрочных интерфейсов, которые в конечном итоге её заменят.

В частности, для объектов, возвращаемых каждой командой в `dbtRunnerResult.result`, не определён полный контракт, поэтому они могут изменяться. Некоторые из возвращаемых объектов частично документированы, поскольку отчасти совпадают с содержимым [артефактов dbt](/reference/artifacts/dbt-artifacts). Как объекты Python, они содержат гораздо больше полей и методов, чем доступно в сериализованных артефактах JSON. Эти дополнительные поля и методы следует считать **внутренними и подлежащими изменению в будущих версиях dbt.**

## Расширенные шаблоны использования {#advanced-usage-patterns}

:::caution
Синтаксис и поддержка этих подходов могут измениться в будущих версиях dbt.
:::

Цель `dbtRunner` — обеспечить в программной среде те же возможности, что и при работе через CLI. Существует несколько продвинутых подходов к использованию, которые расширяют возможности CLI.

<VersionBlock firstVersion="2.0">

### Повторное использование объектов

Передача готового манифеста не поддерживается в v2. Вы не можете передать предварительно созданный объект `Manifest` в `dbtRunner`.

### Регистрация обработчиков обратного вызова

Регистрация обработчиков обратного вызова в `EventManager` dbt не поддерживается в v2.

</VersionBlock>

<VersionBlock lastVersion="1.99">

### Повторное использование объектов {#reusing-objects}

Передавайте заранее созданные объекты в `dbtRunner`, чтобы избежать их повторного создания путем чтения файлов с диска. В настоящее время поддерживается только объект `Manifest` (содержимое проекта).

```python
from dbt.cli.main import dbtRunner, dbtRunnerResult
from dbt.contracts.graph.manifest import Manifest

# используйте команду 'parse' для загрузки Manifest
res: dbtRunnerResult = dbtRunner().invoke(["parse"])
manifest: Manifest = res.result

# анализ манифеста
# например, проверить, что у каждой публичной модели есть описание
for node in manifest.nodes.values():
    if node.resource_type == "model" and node.access == "public":
        assert node.description != "", f"{node.name} не имеет описания"

# повторно используйте этот manifest в последующих командах, чтобы пропустить разбор
dbt = dbtRunner(manifest=manifest)
cli_args = ["run", "--select", "tag:my_tag"]
res = dbt.invoke(cli_args)
```

### Регистрация обратных вызовов {#registering-callbacks}

Регистрируйте `callbacks` в `EventManager` dbt, чтобы получить доступ к структурированным событиям и включить пользовательский логгинг. Текущее поведение обратных вызовов заключается в блокировке последующих шагов; эта функциональность не гарантируется в будущих версиях.


```python
from dbt.cli.main import dbtRunner
from dbt_common.events.base_types import EventMsg

def print_version_callback(event: EventMsg):
    if event.info.name == "MainReportVersion":
        print(f"Мы рады использовать dbt{event.data.version}")

dbt = dbtRunner(callbacks=[print_version_callback])
dbt.invoke(["list"])
```

</VersionBlock>

### Переопределение параметров {#overriding-parameters}

Передавайте параметры как именованные аргументы, а не в виде списка строк в стиле CLI. В настоящее время dbt не выполняет проверку или приведение типов входных значений. Команда должна быть указана в виде списка в первом позиционном аргументе.
```python
from dbt.cli.main import dbtRunner
dbt = dbtRunner()

# эти команды эквивалентны
dbt.invoke(["--fail-fast", "run", "--select", "tag:my_tag"])
dbt.invoke(["run"], select=["tag:my_tag"], fail_fast=True)
```
