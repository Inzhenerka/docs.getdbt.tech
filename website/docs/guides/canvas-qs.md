## Введение {#introduction}

<Constant name="canvas" /> позволяет любому пользователю быстро и просто создавать аналитические модели — опыт в аналитической инженерии не требуется! В этом руководстве вы узнаете о следующем:

- Доступ к <Constant name="canvas" /> и создание новой модели
- Навигация по интерфейсу
- Создание модели с помощью операторов
- Сохранение изменений в <Constant name="git" />
- Поиск модели <Constant name="canvas" /> и её данных

<Prerequisites feature={'/snippets/_canvas-prerequisites.md'} />

:::note Требование для использования Jaffle Shop

В примерах этого руководства используется демонстрационный проект из репозитория [Jaffle Shop](https://github.com/dbt-labs/jaffle-shop) на GitHub. Вы можете использовать собственные данные, но Jaffle Shop представляет собой полнофункциональный проект, удобный для тестирования возможностей dbt. Обратитесь к администратору <Constant name="dbt" /> по поводу его импорта в проект в вашей среде. Перед началом работы администратор также должен выполнить `dbt run` для проекта Jaffle Shop в вашей среде `Production`, иначе вы не сможете ссылаться на исходные модели.

:::

## Доступ к Canvas {#access-canvas}

Чтобы открыть <Constant name="canvas" />:

1. Нажмите **<Constant name="canvas" />** в меню слева.
2. Справа нажмите **Create new workspace**. Откроется новое рабочее пространство с пустой моделью без названия. Для продолжения работы с этим руководством никаких дополнительных действий не требуется, но если вы хотите создать новую модель, нажмите **+Add** на верхней панели навигации, а затем — **Create new model**.

<Lightbox src="/img/docs/dbt-platform/canvas/canvas-create-new-model.png" width="90%" title="Создание новой модели со стартовой страницы Canvas."/>

## Навигация по интерфейсу {#navigating-the-interface}

<Constant name="canvas" /> включает ряд меню, которые открываются при нажатии на значки по краям рабочей области. Когда ни одно из меню не открыто, рабочая область выглядит так:

<Lightbox src="/img/docs/dbt-platform/canvas/canvas-screen.png" width="90%" title="Экран рабочей области Canvas. Количество элементов описано в этом разделе." />

Нажмите на иконку, чтобы раскрыть соответствующий раздел или выполнить действие — в зависимости от её назначения. Доступны следующие элементы:

1. Главное меню (нажмите на **логотип dbt**) и название рабочей области. По умолчанию название задаётся случайным образом, но его можно изменить в любой момент, нажав на него.
2. **Вкладка текущей модели** и её имя. Имя модели задаётся с помощью оператора **Output**.
3. Кнопка со **значком модели**. Позволяет управлять моделями в рабочей области. 
4. Панель **Runs** отображает данные о запусках, включая предупреждения и ошибки.
5. Панель **Previews** отображает предварительные результаты для отдельных операторов.
6. Пункт **Add** позволяет создавать новые модели, редактировать существующие или добавлять seed-файлы.
7. Панель инструментов **Operators** (`Input`, `Transform` и `Output`) содержит строительные блоки для создания модели в редакторе. 
8. Значок [<Constant name="wizard" />](/docs/platform/wizard-platform) (если доступен). Используйте естественный язык для создания моделей в <Constant name="canvas" />.
9. Область **SQL code** отображает SQL-код, в который компилируется ваша модель.
10. Команда **Run** выполняет `dbt run` для модели.
11. Изначально эта кнопка выполняет команду **Commit** для интегрированного сервиса <Constant name="git" />. После первого коммита её название изменится на «Open pull request». Кнопка появится только после того, как вы начнёте работать в области холста.
12. Панель навигации со значками (сверху вниз):
    - Увеличить масштаб
    - Уменьшить масштаб
    - Расположить модель по центру и вписать её в экран
    - Масштабировать до выбранного оператора (выбранный оператор будет увеличен и расположен по центру независимо от того, находится ли он в видимой области экрана)
    - Автоматически расположить отдельные плитки операторов

## Создание модели {#create-a-model}

В этом разделе вы создадите модель с использованием операторов и примерных данных из проекта [Jaffle Shop](https://github.com/dbt-labs/jaffle-shop). В результате вы построите базовую модель, которая трансформирует два набора данных и формирует представление повторных покупок клиентов — полезно, например, при рассмотрении программы лояльности.

Операторы — это сердце вашей модели. Они определяют, какие данные и каким образом будут трансформироваться. Нажмите на иконку **+**, чтобы открыть меню операторов.

Операторы делятся на три типа:
- **Input:** настраивают входные данные (источники).
- **Transform:** изменяют и преобразуют данные.
- **Output:** определяют имя и расположение итоговой модели.

<Lightbox src="/img/docs/dbt-platform/canvas/operators.png" width="90%" title="Меню операторов сбоку от рабочей области Canvas." />

Подробнее об [отдельных операторах](/docs/platform/canvas-interface#operators) можно прочитать, чтобы понять основное назначение каждого из них. Модель dbt, созданная с помощью <Constant name="canvas" />, строится на основе существующих моделей. В этом руководстве будут входные (исходные) модели и выходная модель (та, которую вы создаёте) — _ваша модель_.

<details>
<summary>Подробнее о тайлах операторов</summary>

Операторы перетаскиваются (drag-and-drop) из меню на canvas, и при добавлении создаётся тайл.

Тайлы имеют схожую структуру, но набор полей зависит от функции оператора. Все операторы, кроме **Model**, должны быть соединены с другим тайлом до настройки. После конфигурации их внешний вид становится одинаковым по структуре.

<Lightbox src="/img/docs/dbt-platform/canvas/operator-tile.png" width="90%" title="Плитка оператора с заполненными настройками." />

1. **Коннекторы:** перетаскивайте соединение к коннектору другого оператора, чтобы связать их. Некоторые коннекторы имеют метки L и R — при использовании join они обозначают левую и правую стороны соответственно.
2. **Заголовок:** можно изменить по клику. В примерах и изображениях этого руководства используются названия по умолчанию.
3. **Иконка Play и меню:** позволяет просмотреть данные на любом этапе трансформации, нажав **play icon**. В выпадающем меню есть опция **Delete** для удаления тайла.
4. **Иконка колонок:** число рядом показывает количество колонок в данных на текущем этапе трансформации.

:::tip

Делайте заголовки тайлов операторов уникальными по сравнению с именами колонок — это поможет избежать путаницы. То же относится и к создаваемым alias.

:::

</details>

### Создание модели из уже существующих моделей {#create-your-model-from-pre-existing-models}

Чтобы начать:

1. Откройте меню **Input** и перетащите оператор **Input Model** на canvas.
2. Нажмите **Choose a model** и выберите source-модель `stg_models` из выпадающего списка.
3. В окне со списком колонок нажмите **Select model**.

<Lightbox src="/img/docs/dbt-platform/canvas/one-model-operator.png" width="90%" title="Один оператор модели." />

Теперь у вас есть первая входная модель в <Constant name="canvas" />!

4. Перетащите ещё один оператор **Input Model** на canvas ниже первого и повторите предыдущие шаги, выбрав модель `stg_order_items`.

<Lightbox src="/img/docs/dbt-platform/canvas/two-model-operators.png" width="90%" title="Два оператора моделей на холсте."/>

Теперь у вас есть две input-модели, и вы готовы к трансформации данных.

:::tip

Не видите нужную pre-existing модель? Попросите администраторов dbt убедиться, что она недавно запускалась в окружении Production и не устарела.

:::

### Создание join {#create-a-join}

1. В меню **Operators** нажмите **Transform** и перетащите оператор **Join** на холст справа от исходных моделей. 
    
    <Lightbox src="/img/docs/dbt-platform/canvas/join-not-connected.png" width="90%" title="Соединение, ещё не подключённое к моделям" />

2. Соедините выходы исходных моделей с соответствующими входами оператора **Join**.
   
   <Lightbox src="/img/docs/dbt-platform/canvas/join-connected.png" width="90%" title="Соединение подключено к двум операторам моделей." />

3. В операторе **Join** нажмите **Configure inputs**.
4. В поле **Join type** выберите `Inner`.
5. В обоих выпадающих списках выберите `ORDER_ID` для `stg_orders` и `stg_order_items`.
6. Нажмите **Select and rename columns**, затем **Configure columns**. Выберите следующие столбцы:
   - Из `stg_orders` выберите `ORDER_ID` и `CUSTOMER_ID`.
   - Из `stg_order_items` выберите `PRODUCT_ID`.
   - Столбцы появятся в порядке выбора.
7. Нажмите **значок воспроизведения** в правом верхнем углу оператора **Join**, чтобы проверить результат.

<Lightbox src="/img/docs/dbt-platform/canvas/preview-join.png" width="90%" title="Завершённое соединение с образцом данных." />

:::tip

Ваша работа в <Constant name="canvas" /> автоматически сохраняется по мере выполнения, поэтому, если вам нужен перерыв, вы всегда можете вернуться к сеансу позже. Только не забудьте дать ему уникальное название!

:::

## Улучшение модели {#enhance-your-model}

Вы уже освоили основы работы с моделью в <Constant name="canvas" />! Она успешно объединила две существующие входные модели, но вы хотите дополнительно преобразовать данные, чтобы получить нужный результат: список клиентов, которые повторно покупают одни и те же товары, — для оценки возможности запуска программы вознаграждений для участников клуба лояльности.

### Агрегация данных {#aggregate-data}

Существует несколько способов трансформации данных: пользовательские формулы, фильтры, union. Для простоты добавьте оператор агрегации, чтобы определить, какие клиенты чаще всего покупают повторяющиеся продукты.

1. В разделе **Transform** перетащите оператор **Aggregation** вправо от join.
2. Соедините оператор агрегации с оператором join.
3. В тайле **Aggregation** нажмите **Configure aggregation**.
4. В поле **Group by** сначала выберите `CUSTOMER_ID`, затем `PRODUCT_ID`.
5. Настройте следующие поля:
    - **Function:** Count  
    - **Column:** PRODUCT_ID  
    - **Alias:** count_PRODUCT_ID  

<Lightbox src="/img/docs/dbt-platform/canvas/aggregation.png" width="90%" title="Настроенный блок оператора агрегации." />

6. Нажмите **Play icon**, чтобы просмотреть данные. Результаты уже появляются, но они выглядят неупорядоченными — давайте улучшим их.

:::tip

По мере роста модели вы можете увеличивать и уменьшать масштаб. Зажмите и перетащите пустое место на canvas, чтобы перемещаться по экрану. Используйте иконку **Fit view**, чтобы увидеть всю модель целиком, и **Auto layout**, чтобы автоматически и аккуратно расположить тайлы.

:::

### Добавим порядок {#add-some-order}

Данных много: десятки клиентов и сотни продуктов. Отсортируйте их так, чтобы клиенты шли по возрастанию `CUSTOMER_ID`, а продукты — по убыванию количества покупок.

1. В разделе **Transform** перетащите оператор **Order** вправо от тайла **Aggregation** и соедините их.
2. Нажмите на **иконку карандаша** для редактирования.
3. В поле **Sort order** нажмите **Select column** и выберите `Aggregation1.CUSTOMER_ID`. Установите порядок `Asc`.
4. Нажмите **Add sorting**, затем в новом поле **Select column** выберите `Aggregation1.count_PRODUCT_ID` и установите `Desc`.
5. Нажмите **Play icon**, чтобы просмотреть обновлённые данные.

<Lightbox src="/img/docs/dbt-platform/canvas/order.png" width="90%" title="Настройки плитки оператора упорядочивания данных." />

:::tip

Хотите попрактиковаться самостоятельно? Попробуйте добавить оператор **Filter**, который исключает товары с количеством продаж менее 10 для любого CUSTOMER_ID. Не забудьте запустить preview и проверить корректность данных.

:::

## Настройка output-модели {#configure-your-output-model}

Теперь, когда вы создали модель, нужно настроить имя и расположение выходной модели:
1. Из раздела **Output** перетащите оператор **Output Model** вправо от оператора **Order**. 
2. Соедините операторы **Order** и **Output Model**.
3. В настройках **Output Model** по умолчанию используются имя вашего проекта <Constant name="canvas" /> и стандартный каталог моделей. Нажмите **значок карандаша**, чтобы настроить необязательные поля:
    - Измените поле **Model name**, если хотите, чтобы имя модели отличалось от имени проекта.
    - Измените **File path**, если для моделей <Constant name="canvas" /> вы используете собственный каталог. 
    - Наведите указатель на имя столбца и нажмите значок **-**, чтобы исключить его из выходной модели.
4. Нажмите **значок воспроизведения**, чтобы просмотреть итоговую модель. 

<Lightbox src="/img/docs/dbt-platform/canvas/output-model.png" width="90%" title="Оператор Output Model задаёт имя и расположение итоговой модели." />

:::tip Расположение моделей

Вы можете настроить расположение моделей <Constant name="canvas" />, чтобы хранить их отдельно от других моделей <Constant name="dbt" />. Обратитесь к администраторам dbt за рекомендациями и идеями по выбору расположения моделей <Constant name="canvas" /> и соглашений об их именовании.

:::

## Запуск и публикация модели {#run-and-share-your-model}

Теперь, когда модель готова и даёт нужные данные, пора запустить её и отправить изменения в репозиторий <Constant name="git" />. Перед запуском учтите несколько моментов:

- Запуск предварительного просмотра (на любом этапе процесса) не влияет на состояние вашего хранилища данных. Поэтому вы можете тестировать и разрабатывать модели в <Constant name="canvas" />, не затрагивая ничего за пределами среды разработки <Constant name="dbt" />.
- Когда вы будете готовы использовать эту модель в инструменте, который будет работать с её результатами, запустите её, чтобы материализовать в схеме разработки вашего хранилища данных.
- Когда ваша модель будет готова к использованию в производственной среде, другими пользователями или в рамках оркестрации, зафиксируйте изменения в коммите и откройте пул-реквест.

### Run {#run}

Чтобы запустить модель, достаточно нажать большую кнопку **Run**. В <Constant name="canvas" /> нет командной строки и не нужно запоминать список команд — есть только кнопка **Run**. Нажмите её, чтобы увидеть результаты на панели **Runs and previews**.

<Lightbox src="/img/docs/dbt-platform/canvas/run-results.png" width="90%" title="Результаты успешного запуска на панели «Runs and previews»." />

Это приведёт к [materialize](/docs/build/materializations) данных как `view` в вашей developer-схеме базы данных. После мерджа модели в проект и выполнения `dbt run` в окружениях Staging или Production она будет материализована как view в соответствующих схемах.

<Lightbox src="/img/docs/dbt-platform/canvas/preview-data.png" width="90%" title="Предварительный просмотр преобразованных данных в Snowflake." />

:::tip

В вашем аккаунте <Constant name="dbt" /> Enterprise включён dbt [<Constant name="wizard" />](/docs/platform/wizard-platform)? Очистите рабочую область и попробуйте построить модель из этого руководства с помощью естественного языка, не настраивая операторы вручную.

:::

### Коммит Git {#git-commit}

Модели, созданные в <Constant name="canvas" />, являются частью вашего общего проекта dbt. Они хранятся в папке `visual_editor` внутри каталога `/models`. Всё это происходит автоматически — вам не нужно настраивать пути или каталоги. 

<Lightbox src="/img/docs/dbt-platform/canvas/ve-model-folder.png" width="90%" title="Пример пути к модели Canvas в GitHub." />

Однако эта папка не появится в репозитории <Constant name="git" />, пока вы не закоммитите первую модель. Вернувшись к представлению модели:

1. Нажмите **Commit** в правом верхнем углу.
    - Если вы уже делали коммиты и хотите создать новый, нажмите стрелку рядом с **Create a pull request**, чтобы увидеть опцию **Commit**.
2. Заполните поле **Description** информацией о модели. Если описание длинное, его часть попадёт в заголовок pull request, а остальное — в тело. Это нормально, всё можно отредактировать при создании PR.
3. Нажмите **Commit**.
4. Кнопка **Commit** изменится на **Create a pull request**. Пока что нажмите **Create a pull request** — вы будете перенаправлены к вашему провайдеру <Constant name="git" /> в новой вкладке.

В следующем примере используется GitHub:

<Lightbox src="/img/docs/dbt-platform/canvas/demo-model-github.png" width="90%" title="Пример экрана GitHub, на который вы переходите при создании пул-реквеста из Canvas." />

5. В окне GitHub нажмите **Create pull request**.
6. Заполните поля **Add a title** и **Add a description**. Если описание разделено между ними, скопируйте весь текст в description и задайте более короткий title.
7. Нажмите **Create pull request**.

Вы только что отправили свою первую модель из <Constant name="canvas" /> на проверку. После одобрения и слияния изменений модель будет включена в проект вашей организации и будет запускаться при каждом выполнении `dbt run` в любой среде, где она присутствует. Теперь вы на пути к тому, чтобы стать экспертом по преобразованию данных!

:::tip

Хотите вывести свои навыки на новый уровень? Попробуйте взять SQL-код, сгенерированный для вашей модели в <Constant name="canvas" />, и использовать его для создания модели в [<Constant name="studio_ide" />](/docs/platform/studio-ide/develop-in-studio).

:::

Хотите узнать больше? Обязательно посмотрите наш курс [Canvas fundamentals](https://learn.getdbt.com/learn/course/canvas-fundamentals) на платформе [dbt Learn](https://learn.getdbt.com/catalog).
