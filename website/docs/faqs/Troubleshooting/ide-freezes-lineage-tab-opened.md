Если <Constant name="studio_ide" /> зависает, когда открыты две или более модели и активна вкладка **Lineage**, воспользуйтесь следующими способами обхода проблемы.

### Почему это происходит

<Constant name="studio_ide" /> может зависать, когда вкладка **Lineage** открыта или загружается автоматически и при этом открыты две или более модели, особенно если у какой-либо модели большой или медленно загружающийся <Term id="dag" />.

## Как это может проявляться

- Редактор перестаёт отвечать на действия пользователя.
- Через несколько минут браузер может показать диалоговое окно с вариантами **Wait** или **Exit**.

## Способ 1: Не открывайте вкладку Lineage при запуске

1. Обновите страницу.
2. В консоли оставьте активной другую вкладку (например, **Results** или **Compiled code**), а не **Lineage**.
3. Закройте лишние вкладки моделей, прежде чем открывать **Lineage**.
4. Открывайте **Lineage** только при необходимости.

## Способ 2: Очистите Local Storage для URL вашего аккаунта

Порядок действий зависит от браузера. В DevTools выберите источник Local Storage, соответствующий URL в адресной строке браузера. Например, URL для доступа к вашему аккаунту может выглядеть так: `https://ab123.us1.dbt.com`.

### Google Chrome и Microsoft Edge

1. Откройте страницу <Constant name="dbt_platform" />, которая зависает.
2. Откройте DevTools (щёлкните страницу правой кнопкой мыши и выберите **Inspect**).
3. Перейдите на вкладку **Application**.
4. На левой боковой панели разверните **Storage** → **Local Storage**.
5. Щёлкните правой кнопкой мыши источник, соответствующий текущему URL (например, `https://ab123.us1.dbt.com`), и выберите **Clear**.
6. Обновите страницу и при необходимости войдите в аккаунт повторно.

### Mozilla Firefox

1. Откройте страницу <Constant name="dbt_platform" />, которая зависает.
2. Откройте DevTools (щёлкните страницу правой кнопкой мыши и выберите **Inspect**).
3. Откройте вкладку **Storage**.
   - Если она не отображается, откройте **Settings** в DevTools и включите **Storage**.
4. На левой боковой панели разверните **Local Storage**.
5. Щёлкните правой кнопкой мыши источник, соответствующий текущему URL (например, `https://ab123.us1.dbt.com`), и выберите **Delete All**.
6. Обновите страницу и при необходимости войдите в аккаунт повторно.

### Safari

1. Откройте Safari и перейдите на страницу <Constant name="dbt_platform" />, которая зависает.
2. При необходимости включите функции для разработчиков:
   - Перейдите в **Safari** > **Settings**.
   - Нажмите **Advanced**.
   - Включите функции для разработчиков.
3. Откройте Web Inspector через **Develop** > **Show Web Inspector**.
4. Откройте вкладку **Storage**.
5. На левой боковой панели разверните **Local Storage** и выберите источник, соответствующий текущему URL (например, `https://ab123.us1.dbt.com`).
6. Удалите записи Local Storage для этого источника.
7. Обновите страницу и при необходимости войдите в аккаунт повторно.

## Нужна дополнительная помощь?

Если после применения этих способов зависание сохраняется, [обратитесь в службу поддержки dbt](mailto:support@getdbt.com) и предоставьте:
- HAR-файл (см. [Как создать HAR-файлы](/faqs/Troubleshooting/generate-har-file))
- URL вашего аккаунта
- Название и версию браузера
- Примерное количество открытых вкладок моделей
- Информацию о том, возникает ли проблема только при активной вкладке **Lineage**
